### ⚠ 잔여 1건 — 고테크 세이브에서 `테크 효과 미적용` assert

`★3 이상 세이브 로드 상태에서 self-check 무오류` 가 **테크를 많이 올린 세이브에서
깨진다.** ★3 세이브에 tech 만 바꿔 가며 로드한 실측:

| 세이브의 tech | 결과 |
|---|---|
| `{}` / `spd 50` / `spd 93` / `cap 99` / `gold 100` | 무오류 |
| **`spd 94` 이상** | `테크 효과 미적용` |
| **`cap 100`** | `테크 효과 미적용` |
| **`cost 100`** | `테크 효과 미적용` |

원인은 §1이 고친 것과 **똑같은 유형**이다 — 기준값을 현재 세이브로 재고 있다:

```js
const c0=CHG_MS(), m0=CHG_MAX(), u0=upCost();   // ← 현재 S.tech 기준
S.tech={spd:100,cap:100,cost:100};
console.assert(CHG_MS()<c0&&CHG_MAX()>m0&&upCost()<u0,'테크 효과 미적용');
```

이미 `spd≥94` 면 `CHG_MS()` 가 하한 1500ms 에 걸려 있어 "더 줄어야 한다"가
성립할 수 없다. `cap` 은 100이 최대라 더 커질 수 없고, `cost` 도 100에서 클램프
0.5에 닿는다. 즉 **테크를 끝까지 올린 플레이어일수록 반드시 이 assert 를 본다.**

- **003·004가 만든 결함이 아니다.** 001 검증 때 읽은 forge.html 에도 같은 줄이
  그대로 있었다. 003 §1이 지정한 3건에 포함되지 않았을 뿐이다.
- **피해는 콘솔 노이즈뿐이다.** 004의 `Object.assign(S,snap)` 복원이 뒤에 있어
  저장 데이터는 멀쩡하다 (★4 보존 실측과 별개로 확인).
- 그래도 닫아야 하는 이유: 거짓 assert 가 남아 있으면 사람이 assert 를 무시하게
  된다. 003 제안 1번의 데이터 손실 버그가 세 세션을 조용히 지나간 것도
  "self-check 는 원래 좀 시끄럽다"는 학습 때문이었다.

   반올림 값(4·5·5·4 → 1일)으로 재면 합격, 반올림 없는 값으로 재면 초과다.
   앞 문장이 "반올림 없는 값으로"라고 못 박고 있어 두 규칙이 서로 걸린다.

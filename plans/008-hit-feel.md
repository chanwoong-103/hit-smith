## 목표
캔버스가 배경의 주인이 되고, 화면 한가운데 모루·화로가 선다. 제련 정렬 순간에

스프라이트는 009 몫이다. 여기서는 Phaser `Graphics` 도형과 색만 쓴다 — 형태가
투박해도 **타격의 리듬**이 맞는지를 먼저 본다.

## 변경할 것

### 1. 배경 이관 (한 묶음으로)
- 007이 캔버스를 투명하게 둔 이유가 여기서 해소된다. body 의 화로 잔광
  그라디언트 제거와 캔버스 배경 그리기를 **같은 커밋에서** 한다. 둘을 나누면
  중간 상태에서 배경이 없거나 두 겹이 된다.
- `__view.background` 를 `'css'` → `'canvas'` 로 바꾼다.
- 잔광의 느낌(어두운 바탕 + 아래쪽 주황 발광)은 유지한다. 톤이 바뀌면 002가
  맞춰 둔 패널 대비가 깨진다.

### 2. 중앙 포커스: 모루와 화로
- 화면 중앙에 모루와 화로를 캔버스로 그린다. 세로 레이아웃 재배치는 010 몫이니,
  **지금은 기존 배치를 유지한 채** 중앙 영역만 캔버스로 대체한다.
- 제련 창(재료가 불길 속에서 달궈져 나타나는 연출)을 캔버스로 옮긴다.
  릴 스트립 스크롤 금지는 그대로 (원칙 7).

### 3. 타격 연출 3종
- **카메라 셰이크** — 정렬 성공 시. 등급이 높을수록 강하게, 상한을 둔다.
- **불티 파티클** — 정렬 순간 모루에서 튀는 불티. 개수 상한 필수.
- **바운스** — 획득 장비가 튀어오르는 tween.
- 세 가지 모두 `__view.counters` 에 발생 카운터를 노출한다
  (`shake`, `burst`, `bounce`). **노출되지 않는 연출은 완료로 인정하지 않는다.**
- `prefers-reduced-motion: reduce` 를 존중한다 — 셰이크·파티클을 끄거나 약하게.
  포털 QA 항목이기도 하다.

### 4. 성능 상한
- 파티클 동시 개수 상한을 상수로 두고 `__view` 에 노출한다.
- 방치형이다. **탭을 몇 시간 켜 둬도 프레임이 떨어지지 않아야 한다** — 파티클·
  tween 이 누적되지 않고 회수되는지 확인할 것.

### 5. 이름 교체 (Hit Smith)
- `<title>` 과 화면 명판의 "담금질"을 **Hit Smith** 로 바꾼다. 한국어 부제가
  들어갈 자리가 있으면 `터져라! 대장간`.
- 008이 가져가는 이유: 명판이 캔버스로 다시 그려지는 단계라, 여기서 안 바꾸면
  "담금질"을 한 번 더 그렸다가 나중에 지우게 된다.
- 문서(CLAUDE.md·README·ROADMAP)는 계획 세션이 이미 교체했다. 코드만 남았다.
- checklist 에 옛 이름 문자열을 보는 항목이 있으면 지시서에 올릴 것.

### 6. 【추가·결함】 데스크톱에서 하단 영역에 닿지 못한다
사용자 보고: 별가루를 얻어 무한의 층이 열렸는데 **PC 화면에서 주사위를 굴릴 수
없다** — 하단이 뷰포트 밖인데 스크롤이 되지 않는다. 얻은 보상을 쓰지 못하는
기능 차단이라 미관 작업보다 우선한다.

- 원인을 먼저 확인할 것: 페이지 스크롤이 막혀 있는지(`overflow:hidden` 계열),
  패널이 `height:100vh` 에 갇혀 있는지, 007의 고정 캔버스가 스크롤을 먹는지.
  007의 `#stage` 는 `pointer-events:none` 이지만 부모 쪽 설정이 남았을 수 있다.
- **고치는 방식**: 세로 공간이 부족하면 반드시 도달 가능해야 한다. 하단 관리
  패널에 자체 스크롤(`overflow-y:auto` + 실제 높이 제한)을 주거나 페이지
  스크롤을 살린다. 010의 세로 레이아웃 재구성이 이 영역을 다시 만들지만,
  **그때까지 막아두지 않는다.**
- 데스크톱(1280×720, 1920×1080)과 모바일(380×820) 모두에서 주사위판까지 도달·

- checklist 에 **하단 도달 가능성 검사**를 넣을 자리다 — 검증 세션 몫이니
  지시서에 올려만 둔다.

## 구현 결과 (코딩 세션 2026-08-30)

### 6. 【결함】 데스크톱에서 보상을 못 쓴다 — 원인과 수정 (최우선)

**원인은 페이지 스크롤이 아니었다.** 페이지는 네 크기 모두 정상 스크롤되고
`도전` 버튼도 문제없이 눌린다 (`html/body overflow: visible`, `scrollHeight 1305 >
clientHeight`). 007 의 고정 캔버스도 무관하다 — `pointer-events:none` 이라 휠·터치가
그대로 통과한다.

진짜 원인은 **주사위판 `#dice` 자체**다. `position:fixed; inset:0;
justify-content:center; overflow:visible` 인 전면 모달이라, 내용이 뷰포트보다
높아지는 순간 위아래로 잘리고 **스크롤할 방법이 없다.**

데스크톱에서만 터지는 이유: `#board` 가 4열 `aspect-ratio:1` 그리드라 **폭이
넓을수록 타일이 커진다.** 1280px 폭에서 판 하나가 세로 600px 를 넘어간다.
모바일(380px)에서는 판이 작아 안 넘치니 재현되지 않는다.

수정은 §6 이 명시한 "`overflow-y:auto` + 실제 높이 제한" 두 가지 그대로:
- 모달을 스크롤 컨테이너로 바꾸고, `justify-content:center` 대신 **첫/마지막 자식의
  `margin:auto`** 로 가운데 정렬한다. center 는 넘칠 때 위쪽이 잘려 스크롤로도 못
  닿지만, auto 여백은 남는 공간이 없으면 0으로 접혀 잘리지 않는다.
- 내용 폭 상한(`max-width:420px`)으로 데스크톱에서 판이 부푸는 것을 막는다.

**`#cmp`(정리 팝업)도 같은 구조·같은 결함**이라 함께 고쳤다 (`overflow-y:auto` 는
있었지만 `justify-content:center` 라 넘치면 위가 잘린다 — 장비 교체·판매 버튼이
못 닿게 되는 같은 등급의 기능 차단이다). 지시서가 주사위판만 지목했지만 한 줄짜리
같은 패턴이고, 안 고치면 다음 주에 같은 보고가 올라온다.

**수정 전/후 실측** (`도전` → `굴리기` → `받기` 까지 실제 클릭):

| 크기 | 008 이전 | 008 이후 |
|---|---|---|
| 1280×720 | 판 내용 바닥 737px > 뷰포트 720px · 굴리기 잘림 · **받기 클릭 불가(타임아웃)** | 안 넘침 · 굴리기 보임 · 받기 클릭 · **보상 수령 완료** |
| 1280×600 | 677px > 600px · 같은 실패 | 정상 |
| 1920×1080 | 안 넘침이나 받기 히트 판정 실패 | 정상 |
| 380×820 | 정상 (재현 안 됨) | 정상 |

> 검증 함정 하나: 스크립트에서 `scrollIntoView` 를 먼저 부르고 Playwright `click`
> 을 쓰면 두 스크롤이 겹쳐 hit-target 검사가 흔들려 **멀쩡한 버튼이 타임아웃**
> 난다. 실제로 한 번 오진해서 "1280×720 에서 도전 버튼이 안 눌린다"고 잘못 볼
> 뻔했다. 수동 `.click()` 은 되는데 Playwright 만 실패하면 제품이 아니라 스크립트를
> 먼저 의심할 것.

### 1. 배경 이관 — 무쇠와 숯을 두 겹으로

body CSS 의 `background-image` 잔광과 `background-attachment:fixed` 를 걷어내고
같은 커밋에서 캔버스가 배경을 그린다. `__view.background: 'css' → 'canvas'`.
남은 `background:var(--iron)` 는 캔버스가 못 뜰 때의 바닥색이다.

ART-DIRECTION 의 요구대로 **한 겹으로 뭉개지 않았다**: 위쪽은 무쇠(`#23262B`,
푸른 기), 아래로 내려가며 숯(`#14100E`, 갈색 기)으로 넘어간다. 배경 여백을 세로로
샘플해 색기(B−R)를 실측했다 —

| 위치 | RGB | B−R |
|---|---|---|
| 상단 | 32,34,38 | **+6** (푸른 기 = 무쇠) |
| 중상 | 26,25,26 | 0 (전이 구간) |
| 중하 | 19,15,13 | **−6** (갈색 기 = 숯) |

팔레트 원값이 무쇠 +8 / 숯 −6 이므로 두 색의 관계가 그대로 살아 있다.
패널 대비도 안 깨졌다: 가운데 패널 평균 RGB `[47,48,49] → [47,48,50]`,
아래 패널들 `[38,45,53] → [38,45,53]` (변화 없음).

**캔버스에 칠하는 색은 6색뿐이다.** 밝기 단계는 새 회색을 만들지 않고 알파로만
낸다 (모루 윗면도 회색을 밝히는 대신 열철 35% 를 얹어 "불빛 받는 면"으로 했다).
소스에 남은 `0xffffff` 둘은 렌더되는 색이 아니다 — 불티 텍스처의 흰 원본(항상
`tint:[백열, 열철]` 로 칠해진다)과 화면에 안 그려지는 마스크용 도형이다.

### 2. 중앙: 화로와 모루

`#forge` 패널과 `#hearth` 의 **바탕만** 캔버스로 넘겼다 (`background:none`).
테두리·리벳·릴 타일·게이지는 DOM 그대로 위에 얹혀 checklist 선택자를 하나도
잃지 않았다. 화로 안쪽은 숯, 바닥에서 열철 불빛이 오르고, 그 앞에 모루가 선다.
불빛이 패널로 새지 않게 화로 사각형으로 마스크했다.
캔버스는 고정(fixed)이라 매 프레임 `#forge`·`#hearth` 의 사각형을 확인하고
**바뀐 프레임에만** 다시 그린다 — 스크롤 300px 뒤에도 캐시와 실제 좌표가 일치한다.

### 3. 타격 연출 3종 — 그리고 캔버스가 두 겹이 된 이유

**첫 구현은 눈에 아무것도 안 보였다.** 007 이 캔버스를 `z-index:-1` 에 둔 것은
배경 때문에 옳지만, 같은 캔버스에 불티를 그리면 **불투명한 DOM 패널 뒤로 가려져
한 픽셀도 안 보인다** (스크린샷으로 확인했다). 캔버스 한 장으로는 "배경은 뒤 ·
불티는 앞"을 동시에 만족할 수 없다. 그래서 층을 둘로 나눴다:

- `#stage` (z-index −1) — 배경 · 가운데 패널 · 화로 · 모루 · **셰이크**
- `#fx` (z-index 2, `pointer-events:none`) — **불티 · 바운스**

라이브러리 추가는 없다 (같은 Phaser 3 인스턴스 둘). 010 이 진짜 중앙 캔버스
영역을 열면 한 겹으로 합칠 수 있다 (제안 2번).

정렬 감지는 **CORE 를 한 글자도 안 건드리는 이음매**로 했다. `spin()` 은 CORE 라
손댈 수 없어서, CORE 가 릴에 붙이는 `.spin`/`.hit` 클래스를 MutationObserver 로
본다. 콜백이 스핀 콜백 **끝난 뒤** 한 번만 돌아 그때는 `S.queue` 까지 갱신돼
있으므로 등급도 읽을 수 있다.

정렬 1회(3연·5등급) 실측: `shake 0→1 · burst 0→1 · bounce 0→1`, 분출 17개.

`prefers-reduced-motion: reduce` 에뮬레이션: **셰이크는 아예 안 걸리고**(증가 0),
불티는 17개 → **3개**, 바운스는 이동 없이 페이드만. 카운터는 실제로 일어난 것만
센다 — 그래서 `shake증가:0` 이 곧 "셰이크가 꺼졌다"는 증거다.

### 4. 성능 상한 — 5분 소크

동시 생존 상한 `64`, 1회 분출 상한 `34` 를 상수로 두고 `__view.limits` 에 노출.
`__view.alive` 로 실시간 생존 수를 본다.

5분 동안 2초마다 정렬을 터뜨려 **145회** — 30초 간격 표본 10개 전부:

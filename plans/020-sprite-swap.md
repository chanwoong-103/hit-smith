## 1. 무엇이 오는가

**26장 전부 새 그림이다.** 한 장도 남기지 않는다.

| 묶음 | 장수 |
|---|---|
| 무기 · 투구 · 상의 · 하의 · 장갑 · 신발 × t1·t2·t3 | 18 |
| 근접 몹 t1·t2·t3 | 3 |
| 원거리 몹 t1·t2·t3 | 3 |
| 용사 기본 · 공격 | 2 |

배경 타일 12장은 **그대로 둔다.** 손그림 총량 26 + 12 = **38장 유지**
(`ST3` 상한 38 을 움직이지 않는다).

형식은 018 것 그대로 — `box:[x0,y0,w,h]` + `px`(인덱스 문자열, 길이 w×h, 문자
`0`~`4`). `bakePX` 파이프라인을 그대로 쓴다. **새 포맷·새 파이프라인 금지.**

## 2. ⚠ 외곽선 인덱스 — 두 규약이 공존한다 (2026-09-15 계획 세션 확정)

검증 세션이 찾아낸 충돌이다. 020 초안은 26장 전부에 인덱스 1 테두리를 강제한다고
적었는데, **용사는 015 이래 인덱스 1 을 쓰지 않는다**(밝은 외곽 = idx4).
`SG6` 은 `SPR_HERO.includes('1') === false` 로 그 규약을 검사하고, `MC2` 는
`heroPalette(seg)[4]` 를 외곽선으로 읽는다. 초안대로 갔으면 SG6 이 즉시 FAIL 하고
MC2 는 엉뚱한 팔레트 칸을 재고도 조용히 숫자를 냈을 것이다.

**판정: 용사 규약을 유지한다. 초안이 틀렸다.**

- **장비 18 + 몹 6 = 24장**: 배경에 닿는 칸 **100% 가 인덱스 1**. (실측 확인)
- **용사 2장**: **인덱스 1 을 한 칸도 쓰지 않는다.** 안쪽은 2·3·4, 테두리는 4.
  (실측 확인: idx1 0칸, 테두리 idx4 적중 100%)
- **따라서 `SG6`·`MC2` 는 고칠 것이 없다.** 지금 쓰인 대로 맞다.
  `OC1`·`OC2` 는 24장에만 건다.

**왜 용사만 다른가 — 근거가 이번에 더 무거워졌다.** 32×32 에서 사람 대 사람은
어떤 조합이든 실루엣이 0.6~0.8 로 겹친다(용사 후보 8장 실측, 최선이 0.60).
**용사를 몹과 가르는 것은 형태가 아니라 밝은 외곽선 하나뿐이다.** 실측 대비
(땅 기준) 용사 외곽 9.34 대 몹 외곽 5.55. 여기서 용사를 idx1 로 옮기면 무대에서
자기 말을 못 찾는다.

낮춰야** 화면상 크기가 지금과 같다. 배율을 안 만지면 013 이 맞춰 놓은 간격·

- `SG` 계열은 `SPR_SIZE` 를 상수로 읽으므로 따라온다(015 §3). **그 성질을 깨지
  말 것** — 숫자를 새로 박아 넣지 말고 상수를 읽어라.
- `ST2` 의 무대 좌표는 018 이 `__view.stage` 읽기로 고쳤다. 그대로 둔다.

## 4. 이 그림들이 지키고 있는 것 (전부 실측)

- **외곽선 적중 100%** — 축소가 아니라 테두리 한 칸을 강제해서 만든 값이다
  (원화 그대로면 33~79%). `OC1`·`OC2` 가 볼 자리.
- **무리 판별(1-최근접)**: 몹 6장 전부 통과. 근접 3장 같은쪽 0.80~0.90 /
  다른쪽 0.52~0.78, 원거리 3장 같은쪽 0.62~0.65 / 다른쪽 0.48~0.52.
- **단계 간 겹침은 일부러 높다.** 등급은 부피가 아니라 밀도(ART-DIRECTION
  2026-09-14 정정). t1·t2·t3 경계상자가 거의 같고 안쪽 세부만 는다.
- **좀구멍 메움**: 양자화가 만든 6칸 이하 구멍만 메웠다(하의 48칸·신발 65칸이
  그렇게 생겼다). 원거리 몹의 활 고리·갈비 틈 같은 큰 구멍은 살렸다 —
  원거리 13·24·31칸, 근접 0칸.
- **용사 공격 포즈의 칼날은 원본에서 잘랐다**(폭 229 → 157). 높이를 맞추면
  칼끝이 39칸이라 32칸 격자를 넘는다. **"용사는 무기를 안 든다"는 취향이 아니라
  격자가 강제하는 것이다** — 종전에 적은 근거보다 이것이 진짜 이유다.
- 광원 좌상단 고정.

### ② 배율 — 숫자를 새로 박지 않고 상수에서 파생

`SPR_SIZE` 24 → **32**. 화면 크기를 지키기 위해 배율을 **두 갈래**로 갈랐다:

```
const SPR_FIT  = 3/4;                 // 지시서 §3 의 «3/4»
const SPR_UNIT = SPR_SIZE*SPR_FIT;    // 24 — 단위 배율 1 의 화면 크기
```

- **단위 배율**(`ms`·`scale`)은 **화면 기준**이다. 배치·간격·오프셋은 전부 이
  단위로 쓴다 — 그래서 `ST2` 가 `SS=24` 로 박아 둔 무대 좌표가 **그대로 맞는다**.
- **굽는 배율** = 단위 배율 × `SPR_FIT`. `pxData` 가 비정수 배율을 받도록 칸마다
  목적지 구간을 `round(i·s)…round((i+1)·s)` 로 잡는다 — 칸끼리 경계를 공유하므로
  틈도 겹침도 없고, **정수 배율에서는 예전 블록 복제와 완전히 같은 결과**다.
- `REEL_SCALE()`·`SPR_PX`·`icoPix`·`mobLayout` 은 `SPR_UNIT` 을 읽는다. 숫자를
  새로 박은 자리는 없다. `SG` 계열은 `SPR_SIZE`(32)를 읽어 그대로 따라왔다
  (`SG1` 셀 32×32 · 길이 전부 1,024자 통과).
- **던전 수문장만 예외로 `DGN_SCALE` 그대로 굽는다** — `DG1` 이 그 호출을
  `bakePX(…, DGN_SCALE)` 와 **바이트로 대조**하기 때문이다. 64px 로 구워
  48px CSS 칸에 들어가므로 화면 크기는 019 와 같다. **DG1 은 안 운다.**

### ③ 축소가 «구멍»을 지킨다 (안 하면 원거리가 무너진다)

32칸을 24px 에 넣으면 칸 넷 중 하나가 목적지에서 자리를 잃는다. 그냥 버렸더니
무대 원거리 구멍이 **3.1% → 0.6%** 로 무너졌다 — 013·015 가 「근접=채움 /
원거리=비움」을 색이 아니라 **진짜 구멍**으로 낸 판단이 화면에서 죽는다.
그래서 축소(`scale<1`)에서만 목적지 픽셀이 덮는 칸을 **우선순위로** 고른다:

1. 덮은 칸에 «에워싸인 투명»(구멍)이 있으면 → 투명. **구멍이 이긴다.**
2. 아니면 **외곽선 칸**이 이긴다(구멍을 에워싼 고리가 배경보다 밝아야 구멍으로 읽힌다).
3. 아니면 첫 칠해진 칸. **바깥 투명은 절대 못 이긴다** — 외곽선 한 줄이 통째로
   지워지지 않게(014 의 대비 규약이 거기 산다).

구멍 정의는 `SG7` 이 구멍을 세는 방법과 **같은 flood fill** 이다 — 검사와 구현이
같은 말을 한다. 효과: 무대 원거리 구멍 **0.6% → 1.8%**(3배).

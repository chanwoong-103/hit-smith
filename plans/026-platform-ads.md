## 2. 어댑터 — 게임은 SDK 를 모른다

VIEW 에 얇은 객체 하나. 게임 코드는 이것만 부른다.

```
PLAT.ready        // SDK 가 init 까지 끝났는가
PLAT.adsOn        // 보상형 광고를 지금 제공할 수 있는가
PLAT.rewarded()   // → Promise<boolean>. 끝까지 봤으면 true, 오류·중단이면 false
PLAT.playStart() / PLAT.playStop()
```

SDK 가 없으면 전부 무동작, `adsOn=false`, `rewarded()` 는 즉시 false.
**ROADMAP 이 처음부터 요구한 「함수 교체만으로 끝나게」가 이 모양이다.**

## 3. 광고 훅 2곳

| 자리 | 보상 (원칙 6 — 시간형·정액형만) |
|---|---|
| `#ad` 화로 지피기 | 충전 가득 + 30분 1.5배속 (지금과 같음) |
| `#dad` 주사위 재굴림 | 착지당 최대 2회 (지금과 같음) |

**보상 내용은 바꾸지 않는다. 바뀌는 것은 「보상 앞에 광고가 선다」 하나다.**
DESIGN.md 의 3번째 훅(티켓 +1/일)은 **1.0 범위 밖**이다. 미구현 그대로 둔다.

**CrazyGames 광고 요건 (문서 확인 2026-09-23, 착수 시 다시 읽을 것):**
- 광고 시작 시 **게임 진행을 막는다** — 입력 차단 + 무대 루프 정지.
  (소리는 이 게임에 없다 — 음소거 요건은 해당 없음. 「구현 결과」에 적을 것.)
- **끝까지 본 경우에만 보상.** 오류·중단이면 **보상 없이** 게임을 그대로 이어간다.
- 보상은 **선택**임이 분명해야 하고, 광고 없이도 같은 것을 게임으로 얻을 수
  있어야 한다 — 충전은 시간으로, 재굴림은 원래 없어도 되는 것이라 충족.
- **너무 자주 내밀지 말 것** — 요건이 타이머 쿨다운을 요구한다. 아래 §4.
- 광고를 연쇄로 붙이거나(보상 하나에 광고 둘), 진행 중 전투를 끊고 띄우지 말 것.
- 판 사이 광고(midgame)는 **넣지 않는다.** 이 게임에는 「판 사이」가 없고,
  방치형에 강제 광고는 원칙 1(무관리·방치)의 정체성과 맞지 않는다.

## 4. 충전 광고의 상한 — **숫자로 정한다**

충전 가득은 **한 번에 최대 하룻밤치(600스핀)**다. 횟수를 안 묶으면 광고 유저가
게임을 건너뛴다. 쿨다운과 하루 횟수 상한 둘 다 둔다.

**문턱 (이것으로 상수를 맞출 것):**
- 광고를 매번 최대로 보는 유저의 **w200 도달일이 무광고 대비 10~25% 단축.**
  10% 미만이면 볼 이유가 없고, 25% 초과면 게임을 대체한다.
- 무광고 행은 **기존 밴드 그대로** (Pages 빌드 = 무광고).

**`days.js` 는 기본 출력을 바이트 동일로 둔다.** 광고 시뮬은 `--ads` 인자를 줄 때만
도는 별도 절로 넣을 것. 그러면 `81a6288…` 이 안 흔들리고, 광고 행은 따로 본다.
(`--ads` 가 기본 출력에 한 바이트라도 섞이면 실패다.)

재굴림은 착지당 2회 상한이 이미 있으니 쿨다운만 짧게 둔다(값과 근거를 적을 것).

**쿨다운 표시**: 첫 화면에 분·초 금지(원칙 7). 쿨다운 중에는 버튼을
비활성으로만 둔다. 지금 배속 중 「N분 남음」 표시는 기존 예외 그대로.

## 5. Basic Launch 에서 버튼이 헛돌면 안 된다

CrazyGames 는 **Basic Launch(QA 단계)에서 광고를 꺼 둔다.** SDK 는 있는데
광고가 안 나온다. 그대로 두면 버튼이 보이고, 눌러도 아무것도 안 준다 —
**최악의 첫인상이다.**

`PLAT.adsOn` 이 이것을 가려야 한다. SDK 가 광고 가능 여부를 알려 주는 수단이
있으면 그걸 쓰고, **없으면 상수 하나(`ADS_LIVE=false`)로 두고 Full Launch 에서
사용자가 true 로 바꾸는 한 줄**로 할 것. 어느 쪽인지와 근거를 적을 것.

## 6. 그 밖의 CrazyGames 요건

  읽고 **어느 쪽인지 적을 것.**

    Pages 에서는 여전히 localStorage 다. **`days.js` 기본 출력 바이트 동일.**
  - 필수가 아니면 손대지 말 것.

### ③ 어댑터 — 게임은 SDK 를 모른다

VIEW 머리에 `PLAT` 하나. 게임 코드가 부르는 것은 넷뿐이다.

| | 하는 일 |
|---|---|
| `PLAT.adsOn` | **버튼의 존재 조건.** `(env==='crazygames' && ADS_LIVE) \|\| env==='local'` |
| `PLAT.rewarded()` | `Promise<boolean>`. `adFinished`→true, `adError`·예외·90초 무응답→false |
| `PLAT.playStart/Stop()` | `gameplayStart/Stop`. 탭 숨김·광고 시작에서 stop, 돌아오면 start |

SDK 가 없으면 전부 무동작이고 `adsOn=false`, `rewarded()` 는 즉시 false 다.
상수 넷(`CG_SDK`·`CG_HOSTS`·`ADS_LIVE`·`AD_COOL`/`AD_DAY`)이 한 곳에 모여 있다.

**주입**: `CG_HOSTS` 에 걸리거나 `?cg=1` 일 때만 `<script>` 를 만들어 넣는다.
그 밖에서는 함수가 **첫 줄에서 돌아간다** — 그래서 Pages 의 외부 요청이 0 이다.
스크립트가 안 실리면(차단기 포함) `blocked=true` 로 두고 **SDK 없는 환경과 똑같이**
돈다. 유저를 막지 않는다.

**⚠ node 하네스도 이 줄들을 eval 한다**(`tools/harness.js` 가 스크립트를 통째로
돌린다). 거기엔 `location`·`window`·`document.head` 가 전부 없어서, 바깥을 만지는
자리는 모두 `typeof` 로 가렸다. 하나만 빠져도 smoke·days 가 `ReferenceError` 로 죽는다.

**광고 중 정지는 세 겹이다** — 막 하나로는 안 멈춘다.
`#adwall`(입력을 삼키는 고정 막) · 019 의 `hidden()` 술어에 `PLAT.paused` 를 **합쳐**
두 겹 캔버스를 재우고 · 250ms 틱을 통째로 건너뛴다(충전·자동제련·전투가 다 선다).
`hidden()` 을 재사용한 이유: 「광고 중」은 「탭이 숨은 것」과 처리가 완전히 같다.

### ④ §4 충전 광고 상한 — **문턱을 만족시킬 수 있는 값이 없다**

`node tools/days.js --ads` (기본 출력에 한 바이트도 안 섞인다 — ⑥).

| 접속 | 0회 | 1회 | 2회 | 3회 | 4회 |

| 10분 w200 | 16일 | 14일 (**10.4%**) | 15일 (4.2%) | 15일 (6.3%) | 16일 (0.0%) |
| 30분 w200 | 16일 | 15일 (6.4%) | 16일 (0.0%) | 14일 (**8.5%**) | 16일 (0.0%) |
| 60분 w200 | 15일 | 15일 (0.0%) | 16일 (**−6.8%**) | 15일 (0.0%) | 15일 (−2.3%) |
| 120분 w200 | 16일 | 16일 (0.0%) | 16일 (4.1%) | 16일 (4.1%) | 14일 (14.3%) |

**단조롭지 않고 음수까지 나온다 — 신호가 아니라 잡음이다.** w200 이 14~16일

고해상도로 다시 재도 같다: 90일 최고 웨이브가 0회 773 · 3회 775 · 8회 755

→ **「w200 단축 10~25%」로는 어떤 AD_DAY 도 고를 수 없다.** 이유는 ②와 같다 —
스핀이 병목이 아니라서 광고가 페이싱을 안 민다. **문턱 자체를 계획 세션이 다시
봐야 한다**(제안 ⑵).

**그래서 무엇으로 골랐나 — 요건과 리듬으로 골랐다.**

```
const AD_COOL = 25*60*1000;   // 25분
const AD_DAY  = 3;            // 하루 3회
const DAD_COOL = 30*1000;     // 재굴림 30초
```

- **25분**: 충전 가득은 테크 0에서 600스핀 = 실시간 60분치다. 그보다 **짧은**
  쿨다운이면 「충전이 이미 가득인데 또 권하는」 꼴이 되고, 그보다 훨씬 길면
  한 판(30분 접속)에 한 번도 못 쓴다. 한 세션에 1~2회가 자연스러운 값이다.
- **3회**: 두 세션(아침·저녁)을 덮는다. 페이싱에 해가 없음은 위 표가 보증한다
  (3회와 0회가 같은 밴드다). 요건의 "don't offer too frequently" 를 넘지 않는다.
- **재굴림 30초**: 착지당 2회 상한이 이미 있어 **총량은 더 안 묶는다.** 남은 위험은
  「보상 하나에 광고 둘」로 읽히는 **연쇄**뿐이라 그것만 끊는다.
- 쿨다운 중에는 **버튼을 비활성으로만** 둔다. 분·초 표기 없음(원칙 7).

### ⑦ §6 저장 — **필수다. 그런데 지시서가 허용한 「두 줄 교체」는 불가능하다**

**필수 여부**: 필수다. 기술 요건은 "*(if applicable)* Data module for saving user
game progression" 이고 Data 문서는 "**fully rely on the Data Module save** (for both
guest and logged-in users on CrazyGames) and avoid relying on local saves" 라고
적는다. 이 게임은 진행을 저장한다. (단 **Basic Launch 에서는 SDK 자체가 선택**이다.)

**그런데 손대지 않았다. 두 줄로는 안 되고, 그대로 하면 세이브가 날아간다.**

- 불러오기 줄은 CORE 의 `const S=JSON.parse(localStorage.getItem('forge')||'null')…`
  이고 **스크립트가 파싱되는 순간** 돈다.
- SDK 는 **동적으로 실리고** `init()` 은 **비동기**다. 즉 그 순간 `SDK.data` 는
  존재하지 않는다. 어댑터를 끼워도 부팅 읽기는 **반드시 localStorage 로 떨어진다.**
- 그런데 저장 줄만 `SDK.data` 로 바꾸면 **쓰기는 Data, 읽기는 localStorage** 가 된다.
  → 다음 방문에 진행이 통째로 사라진다. 004 가 고친 「세이브 파괴」와 같은 종류다.

**「두 줄만」이라는 허용 범위 안에 안전한 답이 없다.** 그래서 CORE 를 한 글자도
안 건드리고 제안 ⑴ 로 올린다. 선택지도 거기 적었다.

### ⑩ 못 한 것 — 진짜 SDK 의 `init()` 은 **이 컨테이너에서 측정 불가**

지시서가 콕 집은 물음이다: 「동적 삽입이 실제로 `init()` 까지 도는가」.

- **주입 경로 자체는 확인했다.** `?cg=1` 에서 정확히
  `https://sdk.crazygames.com/crazygames-sdk-v3.js` **한 건**이 나갔고, `?cg` 없는
  Pages 조건에서는 **0건**이었다.
- **그 요청이 컨테이너 밖으로 못 나간다.** 브라우저가
  `net::ERR_TUNNEL_CONNECTION_FAILED` 를 받는다(이 세션의 브라우저는 에이전트
  프록시를 안 탄다). 그 경로에서 어댑터는 **설계대로** 굴렀다 —
  `blocked=true · adsOn=false`, 게임은 멀쩡히 계속. 차단기 유저가 보는 화면이 이것이다.
- 그래서 **문서와 같은 v3 API 모양의 가짜 SDK** 를 실어 어댑터를 끝까지 돌렸다
  (AD5/AD5b). 여기서 안 걸리는 것은 **진짜 SDK 의 `init()` 이 동적 삽입에서도
  resolve 하는가** 하나뿐이다.
- **우회하지 않았다.** 사본 HTML 도, 빌드 스텝도, `<head>` 정적 삽입도 넣지 않았다.

**사용자가 1분이면 끝내는 검문**(022 와 같은 방식으로 남긴다):

```
cd "C:\Users\user\Desktop\claude\방치형 게임 개발"
py -m http.server 8000
```

브라우저에서 **`http://localhost:8000/src/forge.html?cg=1`** → F12 콘솔에서

```
__view.plat
```

- `{ready:true, env:"local", adsOn:true, ...}` 가 나오면 **동적 삽입이 init 까지
  돈다** — 확인 끝. 화로 지피기 버튼이 보이고, 누르면 시연 오버레이가 뜬다.
- `{ready:false, blocked:true}` 면 **스크립트가 안 실린 것**(차단기·네트워크).
- `{ready:false, err:"..."}` 면 **init 이 실패한 것** — 그때가 「동적 삽입이 안 된다」
  이고, 그러면 **여기서 멈추고 알려줄 것.** 복사본 HTML 도 빌드 스텝도 원칙 위반이라
  계획 세션이 판정한다.

⚠ `localhost` 가 아니면 안 된다. Pages URL 에 `?cg=1` 을 붙이면 SDK 가 그 도메인을
`disabled` 로 보고, 어댑터는 `adsOn=false` 로 떨어진다(그래도 게임은 멀쩡하다).

## 제안 (구현하지 말고 여기에 적을 것)

**⑴ 저장을 Data 모듈로 옮기는 일은 별도 지시서가 필요하다 (028 이 자연스럽다).**
필수는 맞다(구현 결과 ①·⑦). 그런데 §6 이 허용한 **「두 줄 교체」로는 안전한 답이
없다** — 부팅 읽기가 SDK 보다 먼저 돌아서, 쓰기만 Data 로 옮기면 세이브가 날아간다.
선택지 셋:
 ① **양쪽에 쓰고 부팅은 localStorage 로 읽는다.** `init()` 뒤에 Data 쪽 `t` 가 더
   새로우면 그때 채택한다(기기 간 이전 전용). 안전하고 CORE 는 두 줄이면 되지만
   **VIEW 에 대조·채택 절차가 붙는다.** 권한다.
 ② **부팅을 SDK 준비까지 미룬다.** 가장 깨끗하지만 CORE 의 `const S=…` 를 옮겨야
   해서 `days.js` 계약을 건드린다. **무거운 변경**이다.
 ③ **027(Basic Launch)까지는 그대로 둔다.** Basic Launch 는 SDK 자체가 선택이라
   요건 위반이 아니다. ①·②는 Full Launch 전에만 끝나면 된다.
 **이 세션의 권고: ③ 으로 027 을 넘기고, 028 에서 ① 을 지시서로 연다.**

**⑵ §4 의 문턱(「w200 단축 10~25%」)은 이 게임에서 만족시킬 수 없다 — 다시 정할 것.**
근거는 구현 결과 ②·④다. 하루 스핀을 **51배**로 늘려도 w200 이 16 → 14일이고
w300 은 오히려 늦어진다. 문턱이 재는 양(w200 도달일)이 **광고가 미는 양이 아니다.**
광고 상한을 숫자로 정하고 싶다면 문턱을 바꿔야 한다. 후보:
 ① **「무광고 유저의 밴드가 안 변한다」만 조건으로 둔다**(지금 만족). 상한은 요건과
   리듬으로 고른다 — 이번에 한 것이 그것이다.
 ② 재는 양을 바꾼다 — 예: **승천 1회까지의 시간**, 또는 **하루 골드 수입**.
   둘 다 스핀에 직접 붙어 있어 광고가 움직이는 양이다.
 ③ 027 뒤 **CrazyGames 분석치**(광고 시청률·재방문)를 입력으로 삼는다. 추측으로
   튜닝하지 않는다는 ROADMAP 원칙에 가장 맞다.

**⑶ 「스핀은 병목이 아니다」는 광고 밖에서도 쓸모 있는 사실이다.**
제련 등급 28 상한 · 승천 리셋 · 별가루가 티켓 2장/일에만 묶인 것 — 이 셋이 곡선을
잡고 있어서 스핀을 51배 부어도 안 움직인다. 「스핀을 더 주는」 보상(광고·이벤트·

**⑺ midgame 광고는 넣지 않았다 — 수익 관점에서 한 번은 다시 볼 것.**

— 10분 1회 10.4% · 30분 3회 8.5% · 60분 2회 −6.8% · 120분 4회 14.3%,
§0 대조 w200 16/14/15/14 · w300 26/26/27/28. **단조롭지 않고 음수가 섞인다는
보고가 맞다** — 옛 문턱으로는 어떤 `AD_DAY` 도 고를 수 없다.
⚠ `--ads` 는 **29분 47초** 걸린다(제안 1).

### §5 `9c` 를 고친 것은 **무르게가 아니라 되게** — 변이로 증명

옛 `9c` 의 알맹이는 「착지당 정확히 2회」다. 새 `9c` 는 광고를 통과시킨 뒤
그 알맹이를 **그대로** 재고(`1,0,0`), 중화한 것은 `dadAt`(쿨다운)뿐이다 —
쿨다운은 `9c` 의 대상이 아니다. `9c2` 가 「광고가 없으면 재굴림도 없다」를 더 본다.

| 변이 | 9c | 9c2 |
|---|:--:|:--:|
| **M-F** `rerolls=2` → `3` (착지당 3회) | **FAIL** `2,1,0` | FAIL(같은 변수를 센다) |
| **M-G** `#dad` 에서 광고를 걷어내고 공짜 재굴림 | **FAIL** `0,0,0` | **FAIL** 남은 재굴림 1 |

**옛 단정이 여전히 운다**(M-F). 검사를 통과시키려고 문턱을 푼 것이 아니라,
계약이 바뀌어 **엉뚱한 자리를 보던 것을 제자리로 옮긴 것**이 맞다.

### §6 곁가지로 확인한 것

- **하루 상한이 새로고침을 견딘다.** `S.adN/adAt/adDay` 는 `save()` 의 `{...S}`
  전개로 그대로 나간다 — 심고 새로고침하니 `adN 3 · adLeft 0` 이 살아 있다.
  (새로고침으로 상한이 리셋되면 무한 광고 보상 구멍이 된다. 안 난다.)
  ⚠ `save()` 는 **3초 스로틀**이라 직후에 `localStorage` 를 읽으면 아직 옛 값이다 —
  검사를 쓸 때 주의할 자리(내가 한 번 헛다리 짚었다).
- `user-select:none` + `-webkit-`/`-moz-`/`-ms-` 접두사 전부 있다(§6 요건).
- 광고 중에는 `save()` 도 같이 멈춘다(250ms 틱 안에 있다). 그 사이 새로고침하면
  오프라인 델타가 광고 시간만큼을 충전으로 돌려준다 — **폭은 광고 한 편(수십 초)**
  이라 피해는 없지만 기록해 둔다.

### 인계

1. **`AD6` 을 지우지 마라.** `AD1`~`AD5b` 여섯은 정지 세 겹의 **깃발만** 본다 —
   M-C·M-D·M-E 가 여섯을 전부 통과하는 것이 실측이다. 광고 중 정지를 손대는
   지시서(028·029)는 `AD6` 의 세 수치(충전·프레임·대기열)를 먼저 볼 것.
2. **`?cg=1` 의 `blocked=true` 는 이 컨테이너의 네트워크 탓이다.** 사용자 실측(⑩)이
   `ready:true · adsOn:true` 로 닫았다. 028 에서 다시 열지 말 것.
3. **`--ads` 는 29분 47초다.** `--measure`(8분)와 합치면 인자를 다 주는 실행이
   40분 가까이 된다. 두 절 다 인자 뒤에 있어 기본 실행(1분 35초)은 멀쩡하지만,
   028 에서 다시 돌릴 일이 있으면 **시드 수나 광고 단계를 줄일지** 먼저 정할 것.
4. `TB8` 은 027-B 가 뒤집는다. 그 전까지 checklist 는 **116 중 115**가 정상이다.

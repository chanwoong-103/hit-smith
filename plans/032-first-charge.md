## 숫자로 본 지금

- 새 세이브의 시작 충전 **30** (`charge:30`, 기본 상태 한 줄).
- 스핀 한 번 ≈ **420ms 연출** + 자동 틱 250ms → 자동이면 **약 0.5초에 한 번.**
- 즉 **첫 30회는 약 15초 만에 끝나고**, 그 뒤는 **6초에 1회**씩 찬다(`CHG_MS` 6000).
- 원칙 7 은 「첫 3분은 순수 스핀만」이라고 적고 있는데, **첫 3분 중 15초만 스핀이다.**

## 판정 — 시작 충전을 `CHG_MAX()`(테크 0 에서 600)로

**근거 ① — `days.js` 는 이미 600 을 주고 재고 있다.** `play()` 의 첫날은
`min(CHG_MAX(), 밤새 충전) + 접속 중 충전` = **600 + 300 = 900 스핀**으로 시작한다.
실제 새 유저의 첫날은 **30 + 300 = 330** 이다. **페이싱 곡선은 처음부터 가득 찬 화로를
전제로 측정됐고, 게임만 그 전제보다 570스핀 인색했다.** 시작을 600 으로 올리면
게임이 곡선 쪽으로 맞춰지는 것이지 곡선을 바꾸는 것이 아니다.
→ `days.js` 는 시작 충전을 읽지 않으므로 **기본 출력 `81a6288…` 은 그대로여야 한다.**
바뀌면 그 자체가 보고 대상이다.

**근거 ② — 스핀은 병목이 아니다** (026 실측: 하루 스핀 51배에도 w200 은 16 → 14일).
첫날 570스핀은 장기 페이싱을 거의 못 민다. **비용은 거의 없고 첫인상은 크게 바뀐다.**

**근거 ③ — 새 상수가 없다.** 이미 있는 `CHG_MAX()` 를 쓴다. 온도계가 **가득 찬 채로**
시작하는 그림도 「화로에 불이 올라 있다」는 첫 화면이다.

**600 이면 첫 세션이 얼마나 되나:** 자동으로 약 5분, 손으로 누르면 그 이상.
대기열(10칸)을 비우는 결정(원칙 4)이 사이사이 끼므로 실제로는 더 길다.
그 뒤는 지금과 같다 — 6초에 1회, 한 시간 비우면 다시 600(오프라인 복원 그대로).
**「다 쓰면 한 시간 뒤 화로가 다시 찬다」가 재방문 고리다.** 이건 건드리지 않는다.

**바꾸지 않는 것:** 충전 속도(`CHG_MS`), 상한(`CHG_MAX`), 오프라인 복원식, 광고 충전
(026 — 충전 가득 + 배속, 하루 3회). 광고 보상은 여전히 의미가 있다: 첫 600 을 다 쓴 뒤다.

### ⚠ 순서 문제 — **숫자를 박았다.** 이유

`CHG_MAX()` 를 `newState()` 안에서 부를 수 **없다.** 고리가 한 바퀴 돈다:

```
CHG_MAX  →  T(k)  →  S  →  (const S = …localStorage… || newState())
```

`newState()` 는 `const S = … || newState()` 줄에서 불리고, 그 줄은 `CHG_MAX` 의
`const` 선언(949행)보다 **위**다 → 그 시점의 `CHG_MAX` 는 TDZ 라 `ReferenceError` 로
부팅이 통째로 죽는다. 순서를 옮기려면 `CHG_MAX`·`T`·`TECH` 뿐 아니라 `S` 까지 끌어올려야
하고, 그건 CORE 를 크게 흔드는 일이다. 지시서의 「CORE 를 최소로 건드리는 쪽」은
**숫자 600 을 박는 쪽**이다. 대신 두 가지를 걸어 뒀다:

1. 그 자리에 「`CHG_MAX` 의 기본값 600 을 고치면 이 줄도 같이 고칠 것」을 주석으로 못박음.
2. **checklist `1a` 가 이제 `CHG_MAX()` 와 대조한다**(아래). 두 값이 갈라지면 운다.

### 30 을 박아 둔 단정 — **하나 있었다** (checklist `1a`)

```
FAIL  1a 첫 접속 충전 30  — chg=600            ← 032 빌드에서 이렇게 울었다
```

값을 600 으로 바꿔 박지 않고 **페이지가 말하는 `CHG_MAX()` 와 대조**하도록 고쳤다:

```js
const chgMax = await page.evaluate(() => CHG_MAX());
chk('1a 첫 접속 충전 = 가득 (CHG_MAX)', Math.abs(+chg - chgMax) <= 1, …);
```

**무르게 한 것이 아니다.** 예전 판정은 「30 언저리(29~31)」였고 지금은 「상한과 같다」다 —
032 가 고친 결함(기본 상태가 상한보다 적다)이 되돌아오면 바로 운다. **변이로 보였다:**
`charge:600` 만 `30` 으로 되돌린 사본 트리에서

```
FAIL  1a 첫 접속 충전 = 가득 (CHG_MAX)  — chg=30 · CHG_MAX()=600 (032 전에는 30)
```

그 밖에 30 을 박아 둔 단정은 **없다.** 훑은 곳: 자체 점검(`console.assert` 전부) ·
`tools/smoke.js` · `tools/days.js` · `devtools/soak.js` · `devtools/checklist.js`.
`smoke`·`soak`·`checklist` 의 다른 `S.charge = …` 들은 **단정이 아니라 조작용 세팅**이라
그대로 뒀다(5·10·40·50 — 각자 재려는 상황을 만드는 값이다).
`docs/DESIGN.md` 의 「첫 접속: 충전 30」은 **600 으로 고쳤다**(괄호로 「032 전에는 30」).

## 제안 (구현하지 말고 여기에 적을 것)

1. **`newState()` 와 `CHG_MAX()` 를 코드로 묶는 길.** 지금은 주석 + checklist `1a` 로

   **위**에 두고 두 곳이 그것을 읽게 하면 된다(상수 하나 신설 · CORE 두 줄).
   032 는 「새 상수가 없다」가 판정 근거 ③ 이라 하지 않았다 — 다음에 이 자리를 만질 때.
2. **`tbOpen` 의 세이브 씨앗이 아직 `charge: 30` 이다**(checklist 1224행). 단정이 아니라
   TB1~TB8 이 쓰는 **조작용 세이브**라 그대로 뒀지만, 그 결과 **TB8 35칸은 「충전 30 인
   첫 화면」을 본다** — 이제 진짜 첫 화면이 아니다. `#spin` 글자가 「제련 30」 →
   「제련 600」으로 길어지는데 TB8 은 그 폭 변화를 못 본다. 씨앗을 600 으로 올릴지
   두 벌로 돌릴지는 검증 세션 판단이 필요하다.
3. **대기열 10칸이 실제 문턱이다**(위 실측). 「첫 세션 5분」은 사람이 대기열을 계속

   화면이 무엇을 말해 주는지(지금은 조용히 멈춘다)가 다음 이탈 지점이다.
4. **031 제안 ⑴(`#gear` 가로 넘침 검사)·⑸(`#manage` 넘침)은 그대로 열려 있다.**

#### ① CORE 첫 절 — 이전 빌드 없이 바이트로 닫았다

컨테이너 초기화로 031 빌드(`a75e3b44…`)가 **사라져** 「전·후 대조」를 그대로는 못 한다.
**되돌려서** 증명했다: 032 가 넣은 주석 10줄(**1,025 B**)을 걷고 `charge:600`→`charge:30`
(**1 B**)로 되돌리면 CORE 첫 절이 **정확히 15,441 B** — 031 이 적은 **15,442 B**
(경계 관례 1 B 차)다. 즉 **첫 절 증가분 1,026 B = 주석 1,025 B + 세 글자 중 1 B**,
**다른 바이트는 하나도 안 움직였다.**
둘째 절(자체 점검)은 비교 대상이 없어 절대 바이트 대조가 **불가능**하다 —
효과로 본다(`days.js` md5 동일 · 자체 점검 한 줄 동일 · smoke 19/19).
이 한 칸만은 「재현했다」가 아니라 **「같은 값을 다시 못 뜬다」**로 적어 둔다.

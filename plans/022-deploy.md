## 왜 배포가 먼저인가 (계획 세션 판정 2026-09-23)

쌓인 제안 넷(019-1·019-2·020-5·021-4)보다 배포를 앞에 둔다. 근거 넷.

**① 배포 안 된 게임은 0원이다.** 이 프로젝트의 목적은 수익이고, 지시서 22개를
쌓는 동안 게임은 **한 번도 누구 손에 가 본 적이 없다.** 내부 품질을 한 바퀴 더
돌기 전에 바깥에 한 번 내놓는 것이 맞다.

**② 배포가 실기기 확인의 전제에 가깝다 — 이게 결정적이다.**
지금 밀린 실기기 확인이 다섯이고, 쌓인 제안 넷 중 **셋이 체감 판정 대기**다
(019-1 `DIE_MS` 체감 / 020-5 몹 잉크 / 021-4 재배치). 즉 **실기기가 병목이고,
제안을 먼저 정리해 봐야 판정이 안 난다.** 지금은 파일을 손으로 폰에 옮겨야
확인이 되는데, 배포하면 URL 하나로 끝난다. **병목을 푸는 일을 먼저 한다.**

**③ 구조적으로 미룰 이유가 없다.** 006 은 루트 `index.html` 리다이렉트와
`.gitignore` 뿐이라 `forge.html` 을 안 건드린다. 락을 안 잡으므로 제안 정리와
**병렬로 돌 수 있다.** 순서를 다투는 관계가 아니다.

**④ 제안 넷은 전부 내부 품질이고 아무도 불평하지 않았다.** 유휴 duty 11%,
상수 하나의 과장, 무리 재배치 — 사용자가 보고한 것은 하나도 없다.
사용자가 실제로 보고한 것(장갑 손가락·소멸 순서)은 전부 처리됐다.

**반론도 적어 둔다.** 019 제안 2(CORE 250ms 틱이 숨은 탭에서도 돈다)는 모바일
배터리에 직결되고 배포하면 바로 드러난다. 그런데 **얼마나 먹는지 잰 적이 없고**
CORE 변경이라 days.js 를 건드린다. **숫자 없이 CORE 를 여는 것보다, 배포하고
실기기에서 재서 근거를 만든 뒤 여는 것이 맞다.** 023 으로 넘긴다.

## 3. GitHub 에 올리기 — 둘 중 하나

저장소 이름 제안: **`hit-smith`**
(URL 이 `계정.github.io/hit-smith/` 이 된다. 한글·공백은 URL 에서 깨지므로 피한다.)

### A. `gh` CLI 가 있으면 — 두 줄

```
gh auth status
gh repo create hit-smith --public --source=. --remote=origin --push
```

`gh auth status` 가 로그인 안 됐다고 하면 `gh auth login` 을 먼저.
(이 세션은 사용자 컴퓨터 셸이 없어 **인증 여부를 확인하지 못했다.**)

### B. `gh` 가 없으면 — 웹에서 만들고 연결

1. github.com → New repository → 이름 `hit-smith` → **Public** →
   README·.gitignore·license **전부 체크 해제** (이미 있다) → Create.
2. 아래에서 `계정` 을 본인 아이디로 바꿔서:

```
git remote add origin https://github.com/계정/hit-smith.git
git push -u origin main
```

**Pages 는 무료 계정에서 Public 저장소만 된다.** Private 으로 만들면 안 켜진다.

## 4. Pages 켜기 (최초 1회)

`gh` 가 있으면 한 줄 (저장소 폴더 안에서 — `{owner}` 는 gh 가 채운다):

## 제안 (구현하지 말고 여기에 적을 것)

**⑴ 대용량 그림 넷(29MB)은 어디에 남는가 — 완료 조건이 요구한 항목.**
지금 상태: **로컬 폴더에 그대로 있고, 저장소에는 안 들어간다.** 즉 이 넷만은
GitHub 이 백업해 주지 않는다. 권하는 처리는 둘로 나뉜다.
 ① 루트 `Gemini_Generated_Image_2gdqo22gdqo22gdq.png` 는
   `docs/ref/016-screen-layout.png` 와 **md5 가 같다**(`6b740c12…`, 6,717,089 B)
   — 같은 파일 두 벌이다. 루트 쪽을 **지우는 것을 권한다.** 지우면 `.gitignore`
   줄 하나도 같이 빠진다. (006 제안 1 은 이 중복을 `002-ui-concept.png` 짝으로
   적었는데, 크기만 보고 판단한 듯하다. 실제 짝은 016 이다 — md5 로 확인했다.)
 ② 남는 셋(002 둘·016 하나, 22.7MB)은 **WebP 로 줄여 `docs/ref/` 에 다시 넣고
   추적하는 것을 권한다.** 개념 스케치라 픽셀 정확도가 필요 없다 — 폭 1600px
   WebP 면 장당 200~400KB 로 떨어져 021 시트(593KB)보다 가벼워진다. 그러면
   `.gitignore` 의 대용량 절이 통째로 사라지고 **저장소가 다시 백업 노릇을 한다.**
 원본을 꼭 남겨야 한다면 별도 클라우드 드라이브가 맞고, git-lfs 는 **권하지 않는다**
 — 무료 한도가 있고 「빌드·도구 없음」 원칙에 도구가 하나 늘어난다.
 **판단은 계획 세션 몫이라 022 는 아무 파일도 지우거나 변환하지 않았다.**

**⑵ `Claude outputs/` 26개가 추적된다 — 의도인지 확인 필요.**
리허설에서 추적 파일 100개 중 **26개**가 이 폴더다(docs 38 다음으로 많다).
세션 산출물 보관함이라 계속 늘어날 자리이고, 공개 저장소에 들어간다.
006 의 "저장소 = 프로젝트 폴더 그대로" 결정에는 부합하므로 **막지 않았다.**
막을지 말지는 계획 세션이 한 번 정해 주는 게 좋다.

**⑶ `.nojekyll` 빈 파일 (006 제안 2 재상신).** 지금은 Pages 가 Jekyll 빌드를
거친다. 없어도 동작은 하지만(④에서 확인), `_` 로 시작하는 파일이 생기는 순간
조용히 누락되는 함정이 열린다. 빈 파일 하나로 빌드 자체를 끄는 게 「빌드 없음」
원칙에 더 맞다. **지시서 「변경할 것」에 없어서 이번에도 안 넣었다.**

**⑷ 지시서에 사용자 컴퓨터 절대 경로가 공개된다 (006 제안 3 재상신).**
이 문서에도 `C:\Users\user\...` 가 들어간다. 사용자명이 공개돼도 상관없는지
한 번은 확인하고 넘어가는 게 좋다. 신경 쓰인다면 명령 목록을
`cd <프로젝트 폴더>` 로 바꾸면 되지만, 그러면 붙여넣기가 안 된다 — 맞바꿈이다.

**⑸ PWA 캐시 대상은 `index.html` 과 `src/forge.html` 둘 다 (006 제안 4 유지).**
리다이렉트 페이지가 캐시에서 빠지면 오프라인에서 `/` 가 죽는다.

**⑹ 검증 세션은 「문서 산출물」도 파일로 확인할 것.**
006 의 구현 결과와 실물 `README.md` 가 **어긋나 있었다**(①). 코드 산출물은
tools 가 잡지만 문서 산출물은 아무도 안 본다. 「README 에 절을 추가했다」 같은
항목은 **파일을 열어 그 문자열이 있는지** 보는 것으로 족하다.

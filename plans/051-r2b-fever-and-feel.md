- `rhyOutLat()` — `ctx.outputLatency`(0 이거나 없으면 `baseLatency`)를 박 기준점에 **더한다**. 049 검증이 본 「바늘이 들리는 박보다 ≈37ms 앞선다」의 원인이 이것이다.
- 사람 보정 `hs.offset`(−200~+200 · 10ms 단위 · **`localStorage` · 세이브 `S` 에 안 들어간다**). 정보 팝업에 슬라이더 + **「맞춰 보기」**(박에 맞춰 여덟 번 치면 평균 시차를 보정값으로).
- 바늘과 판정이 **같은 기준점**을 쓰므로 둘이 함께 밀린다(한쪽만 밀면 「보이는 박에 쳤는데 아쉬움」이 된다).

| 검사 | 결과 |
|---|---|
| **B1** 출력 지연 0 / 40 / 200ms 흉내 | 격자 밀림 = 정의대로의 지연 **10.0 / 40.0 / 200.0ms** · 「들리는 박」에 친 탭 **6/6 · 6/6 · 6/6 완벽**(평균 −3.8 / −4.9 / +0.3ms) |

### ② 피버 게이지 — 천장을 대체 (CORE)

- `PITY()` → **`FEVER_MAX()`**(값은 그대로 `20×릴`) · `FEVER_MS=15000` · `FEVER_FILL={완벽 3, 정확 2, 좋음 1, 아쉬움 0}`.
- **`feverAdd(grade)`** — VIEW 의 손 판정이 부르는 **유일한 입구**. 견습생 타격은 이 길을 지나지 않는다(그래서 자동은 못 채운다). 피버 중엔 안 채운다.
- `spin()` 의 천장 분기 → **피버 분기**: 게이지 가득이면 그 제련이 **특별 주문**(전 릴 정렬 · 고정 토큰이 있으면 그 부위 — 옛 천장과 같은 규칙이라 원칙 4 의 결정 ④ 가 그대로 산다) → 그 순간 게이지 0 + 피버 15초 → 피버 중 모든 제련은 **2연 이상 보장**(이미 2연 이상이면 그대로 둔다).
- **자연 전 릴 정렬이 게이지를 비우던 규칙은 없앴다** — 게이지는 손만의 것이다.
- 저장: `S.pity` 는 **뜻만** 피버 게이지로 바뀌고 새 필드는 **`S.feverUntil` 하나**다. 불러오기 한 줄(`S.feverUntil=0`)로 **오프라인 동안 피버는 흐르지 않는다**(방치로 2연 보장을 쌓아 두는 길을 막는다).
- 자체 점검 다섯 줄을 더했다(피버 문턱 · 자동은 못 채움 · 손 판정 +3 · 특별 주문이 고정 부위·전 릴 정렬·게이지 0·피버 시작 · 피버 중 24회 전부 2연 이상 · 피버 중엔 안 채움).
- ⚠ **§2② 밖의 CORE 두 줄을 뒀다 — 판정해 주기 바란다.** `let fgLastBest, fgLastSpecial, fgLastGrade`(선언 1줄) + 420ms 콜백 안의 대입 1줄이다. **세이브 필드가 아니라 모듈 변수**이고 계산에 안 쓰인다(`days.js` 기본 출력 불변이 그 증거). 둔 까닭: §2② 가 요구한 자체 점검(「피버 중 2연 보장」·「특별 주문이 전 릴 일치」)을 하네스에서 재려면 결과를 읽을 길이 있어야 한다 — 릴 DOM 으로 재면 `querySelectorAll` 이 빈 배열이라 **공허하게 통과**한다. 연출(⑤)과 검사(F4)가 같은 값을 읽는다.

### ③ 피버 화면·소리

- 압력계(`#pity`)가 **피버 게이지**가 됐다 — 요소·자리·바늘은 그대로, 차오르는 값이 `S.pity`, 가득이면 「특별 주문 준비」(`fever.ready`), 피버 중엔 **남은 시간**이 줄어드는 금색 막대(`.fever`).

- **피버 곡은 게이지 70% 에서 미리 싣는다**(046 §7-b′ 의 순서). 게이지가 **한 번에** 찬 판에서는 틱이 70% 를 못 보므로, 피버가 열릴 때 한 번 더 부르고 **늦게 도착하면 그 자리에서 갈아탄다**(안전망 — B3 이 처음 그 구멍으로 울었다).

### ⑥ 이 레그에서 **새로 찾아 고친 결함** — 자체 점검이 화면을 얼려 놓았다

다시 돌린 checklist 가 울었다: **TB7 · TB8 · AP1 셋이 「`#asc` 가 `display:none` 이라 못 누른다」**로 실패(050 통과본에서는 141/0).

### `days.js` 새 기준 md5 — **바뀌지 않았다** (`81a6288ee480f80cc9a6c014de4e1826`)

지시서는 새 기준 md5 를 예상했지만 기본 출력이 **바이트 동일**하다. 왜 그런지 표로:

|---|---|
| `PITY()` → `FEVER_MAX()`(값 동일) | **안 지난다** — `doSpins()` 는 천장을 모형화한 적이 없다(릴을 직접 굴린다) |
| `spin()` 의 천장 분기 → 피버 분기 | **안 지난다** — `doSpins()` 는 `spin()` 을 부르지 않는다 |
| `S.pity` 의 뜻 · 새 필드 `S.feverUntil` | **안 지난다** — 둘 다 안 읽는다 |
| `feverAdd()`·`feverOn()`·`feverLeft()` | **안 지난다** — 부르는 곳은 VIEW 의 손 판정뿐이다 |
| `fgLastBest`·`fgLastSpecial`·`fgLastGrade` | **안 지난다** — 연출·검사만 읽는다 |
| `STR` 새 키 11개(ko·en) | **안 지난다** — 하네스에 `navigator` 가 없어 LANG 이 'ko' 이고, 글자는 계산에 한 글자도 안 쓰인다(034 부터의 성질) |

즉 **피버의 영향은 `--fever` 계측 블록에서만 보인다**(§5 표). 「기본 출력 md5 불변」은 이번에도 「CORE 의 **계산**을 건드리지 않았다」의 증거로 그대로 쓸 수 있다.

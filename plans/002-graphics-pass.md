# 002 — 그래픽 패스 (담당: 디자인 세션)

상태: **검증 통과** (검증 세션 2026-08-29) · `3b` 갱신은 검증 세션이 처리
(checklist 61 → 63항목). forge.html 쓰기 락 해제 상태 유지.
— 아래는 디자인 세션 인계 시점의 원래 기록:

## 목표
대장간 제련 컨셉을 시각적으로 완성한다. 릴 심볼을 이모지에서 인라인 SVG로
교체하고, 정렬 순간의 타격감을 화염/불꽃 연출로 강조한다 (ROADMAP 2번).

## 변경할 것
- 릴 심볼 6부위(무기·모자·상의·하의·장갑·신발)를 인라인 SVG 아이콘으로.
  `<symbol>`/`<use>` 재사용으로 한 벌만 정의. 파일 에셋·외부 이미지 금지.
- 고정 토큰(⬢)·천장 게이지·재화 아이콘도 같은 스타일로 통일 (선택이 아니라
  일관성 필수 — 이모지와 SVG가 섞이면 더 싸 보인다).
- 정렬 순간: 일치한 릴에 화염/불꽃 1회성 CSS 애니메이션
  (transform·opacity·filter만, 파티클 라이브러리 금지).
  기존 니어미스 하이라이트·3연+ 강조 메시지의 동작은 유지하고 스타일만 강화.
- 전체 톤 정리: 금속·숯·화염 팔레트로 버튼·패널 질감 통일.
- 모바일 폭 ~380px에서 레이아웃 유지.

## 바꾸지 말 것
- 등급색 15종(--g1~--g15) — 배색 체계 변경 금지.
- 전투 수식·상태·저장 로직·수치 일절 (표시 계층만).
- renderFast: 틱당 innerHTML 재구성 금지. SVG는 정적, 애니메이션은 클래스 토글.
- 카지노/슬롯머신 비주얼·용어 금지 (원칙 7) — 릴은 "제련로의 재료 슬롯"으로
  보이게. 레버·코인·777·네온류 모티프 금지.
- 단일 파일, 무의존, 웹폰트 금지.

레퍼런스 이미지의 **느낌**을 가져오되, 아래 번역 규칙을 지킨다.

채택할 것:
- 금속·숯·화염 팔레트, 리벳 박힌 강판 프레임, 화로의 주황 발광, 증기 분위기.
- 압력계 게이지 모티프 — 천장 게이지를 "화로 압력계"로 표현 (스핀마다 바늘
  상승, 가득 차면 적색 구간 = 강제 정렬). 카지노 냄새 없는 최고의 은유.
- 음각/장식 프레임의 부위 아이콘 스타일 (단, 등급 테두리색은 --g1~--g15 그대로.
  레퍼런스의 임의 배색 따라가지 말 것).
- 스탯 패널의 온도계형 세로 게이지, 금속 명판에 새긴 타이틀.

걸러낼 것 (원칙 7 위반 요소):
- 슬롯머신 캐비닛 실루엣 금지. 릴 3~5개는 "제련로 안의 도가니/거푸집 슬롯"으로
  — 세로로 긴 흰 릴 창 대신, 화로 창(hearth window) 안에 재료가 달궈지는 형태.
  릴 회전 연출도 릴 스트립 스크롤이 아니라 화염 속에서 심볼이 담금질되어
  나타나는 페이드/글로우로.
- 레버·코인 트레이·777·"pity" 같은 겜블 용어 화면 노출 금지 (천장 게이지 라벨은
  "화로압" 등 제련 용어로).
- 주사위 판: 레퍼런스의 원형 휠+포인터는 룰렛으로 읽힌다. 8칸은 모루/석판 위
  평면 사각 트랙으로, 말이 이동하는 보드게임 형태 유지 (주사위 자체는 OK).

등급별 발전 아이콘 (레퍼런스 2: docs/ref/002-grade-progression.png):
- 장비 아이콘이 등급에 따라 눈에 띄게 발전해 보이게 한다. 단, 부위×등급
  개별 드로잉(90종) 금지 — 원칙 3 "콘텐츠는 공식으로"는 아이콘에도 적용된다.
- 구성: 부위당 실루엣 **3단계** (등급 1~5 조악한 형태 / 6~10 정제된 형태 /
  11~15 장식된 형태) × 등급색(--g1~--g15) 스트로크·글로우 × 상위 구간
  이펙트(11+ 은은한 발광, 14~15 화염 오라). SVG `<symbol>` 18개 + CSS 공식으로
  15등급 전부 커버.
- 릴 심볼·대기열 카드·착용 슬롯이 같은 심볼을 공유할 것 (한 벌 정의 재사용).
- 반지·목걸이는 **그리지 않는다** — 부위 7~8은 미확정 예약 (DESIGN.md에 없는
  시스템은 존재하지 않는 것). 레퍼런스의 8부위 진행도 패널도 구현 대상 아님.
- 레퍼런스의 등급 배색·건너뛰는 등급 표기는 무시 — 등급 1~15 연속, 색은
  --g1~--g15 고정.

구현 제약 (레퍼런스는 래스터 일러스트지만 우리는 아니다):
- 페인팅 질감을 흉내내지 말 것. 인라인 SVG + CSS 그라디언트/섀도로 도달

## 구현 메모 (디자인 세션)

- 심볼: `<symbol id="s-<부위>-<1|2|3">` 18개 + 재화·UI 7개(`s-gold`/`s-token`/
  `s-dust`/`s-ticket`/`s-flame`/`s-charge`, 주사위는 인라인). 문서 상단
  `<svg id="sprite" style=display:none>` 한 벌, 전부 `<use>` 재사용.
- 등급 15종은 `plate(part, g)` 하나가 만든다: 실루엣 `TIER(g)=g≤5?1:g≤10?2:3`
  × 인라인 `color:--gN` (심볼의 `stroke="currentColor"` 가 받음) × `.gl`(11+ 발광)
  · `.au`(14+ 화염 오라). 부위×등급 개별 드로잉 0건.
  ※ `<use>` 그림자 DOM 은 상속 속성만 넘어간다 — 심볼 안 색은 클래스가 아니라
    프레젠테이션 속성으로 박았다. 클래스로 바꾸면 등급색이 통째로 죽는다.
- 릴 심볼·대기열 카드·착용 슬롯이 같은 심볼을 공유한다 (릴은 중립 2단계).
- 천장 게이지 → 화로 압력계. 바늘은 `#pneedle` 의 transform 한 줄만 갱신
  (renderFast, innerHTML 재구성 없음). 라벨은 `화로압 n/N`, 가득 시 `▣ 임계압`,
  강제 정렬 메시지도 `▣ 임계압 정렬` (겜블 용어 화면 노출 제거).
- 화로 창 왼쪽 세로 온도계 = 남은 충전. `#thermf` 의 height 한 줄만 갱신.
- 이모지 0건 (⚔⛑🎽👖🧤🥾📺🎲🎟, ◈·✦ 포함 전부 SVG 로 교체).

## 제안 (구현하지 말고 여기에 적을 것)

- **devtools/checklist.js:240 갱신 필요.** `chk('3b 가득 문구 표시',
  pity.txt.includes('천장'), ...)` 가 지시서의 "천장 라벨을 제련 용어로" 지시와
  정면으로 충돌한다. 라벨이 `▣ 임계압 …` 이 되면서 이 항목만 FAIL 로 남는다
  (나머지 60항목 PASS). 디자인 세션 권한 밖이라 손대지 않았다 — `'임계압'`
  또는 `/임계압|화로압/` 으로 바꿔 줄 것.
- **"스탯 패널의 온도계형 세로 게이지"는 화로의 충전 온도계로 번역했다.**
  능력치(공격력·체력)에는 눈금의 기준이 될 상한이 없어서 세로 게이지를 달면
  의미 없는 장식이 된다. 충전은 `CHG_MAX()` 라는 진짜 상한이 있어 온도계가
  그대로 성립한다. 능력치 쪽에도 게이지를 원하면 기준값(예: 현재 웨이브
  요구 전투력)을 계획 세션이 정해 줘야 한다.
- 적 무리(`.foe`)는 아직 사각 블록이다. 같은 심볼 체계로 근접/원거리 실루엣을
  주면 화면이 한 벌로 붙는다. 001 산출물이라 002 범위 밖으로 두었다.
- 타워 일러스트(무한의 층 스플래시)는 지시서대로 미구현.

### 2. `3b` 갱신 — DESIGN.md 확정 라벨 기준으로 교체 (지시서 제안 1)

화로압  50%  바늘 rotate(0deg)    라벨 "화로압 30/60"

게이지 DOM 노드 7개 동일(재구성 없음): true
온도계 충전 0/50/100% → height 0% · 50% · 100%

등급 이펙트가 공식으로 도는 것도 확인했다:

```
g1,g5   → #s-weapon-1  class="pl"        (실루엣 1단계)
g6,g10  → #s-weapon-2  class="pl"        (2단계)
g11,g13 → #s-weapon-3  class="pl gl"     (3단계 + 발광)
g14,g15 → #s-weapon-3  class="pl gl au"  (+ 화염 오라)
색은 인라인 color:var(--gN) → 심볼의 stroke="currentColor" 가 받음
```

**오탐 하나 기록해 둔다**: 화면 텍스트 전수 검사에서 `777` 이 한 번 걸렸는데,
소스에 리터럴 `777` 은 **0건**이고 난수 장비의 수치(전투력·별가루)가 우연히
그 숫자를 만든 것이었다. 다음 세션이 같은 검사를 돌리다 놀라지 않게 적어 둔다 —
`777` 은 문자열이 아니라 숫자로 걸린다.

### 발견 — 반려 사유 없음. 계획 세션에 넘기는 참고 2건

1. **`★` 는 화면에 남은 유일한 비-SVG 기호다.** 승천 표시(`#star`)·승천 버튼·
   승천 확인창에 쓴다. 유니코드상 이모지가 아니라 텍스트 기호라(`▣`·`◆`·`◇`
   와 같은 부류) "이모지 0건"은 성립하고, `▣` 는 DESIGN.md 가 라벨로 확정한
   글자다. 다만 `★` 만은 DESIGN.md 에 근거가 없다 — 별 표시를 `s-flame` 류
   심볼로 옮길지, 아니면 `▣` 처럼 표시 규약에 한 줄 추가해 확정할지 정해 두면
   다음 세션이 헷갈리지 않는다.
2. 지시서 「제안」의 나머지 3건(스탯 온도계 번역 근거 / `.foe` 심볼화 /
   타워 일러스트)은 전부 계획 세션 소관이라 손대지 않았다. `.foe` 심볼화는
   위 스크린샷에서 실제로 눈에 띈다 — 다른 곳이 전부 SVG 로 바뀌면서 전투
   패널의 사각 블록만 이전 세대로 남았다.

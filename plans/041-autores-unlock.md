## 계획 세션이 같이 적어 두는 대가 — 알고 고른 것이다

- 033 이 고친 **「자동을 켜고 손을 떼면 5.3초 만에 대기열이 차서 멈춘다」가 첫 승천(약 5일차) 전까지 다시 생긴다.**
  그동안 대기열은 사람이 정리한다(원칙 4 ③ 「교체하나 파나」가 첫 주기 내내 사람의 결정이 된다 — 033 전의 설계).
- 그래서 **멈춘 상태가 「고장」이 아니라 「할 일」로 읽혀야 한다.** 이 지시서의 ③이 그것이다.
  출시 관문 P1(첫 플레이어)·P5(장르 고인물)가 이 순간을 짚으면, 계획 세션이 사용자에게 다시 올린다.
- 페이싱(`days.js`)은 **바뀌지 않는다** — `days.js` 는 「뽑을 때마다 사람이 완벽하게 정리한다」를 전제로 잰다.
  실제로 달라지는 것은 「자리를 비운 동안 제련이 서는 시간」이다. 그 크기를 ⑤에서 잰다.

## 변경할 것 — 전부 VIEW. CORE 는 `STR` 키 추가 말고 0줄

`S.autoRes` 를 읽는 곳은 이미 전부 VIEW 다(1195·1201 CORE 두 줄은 기본값·불러오기 보정 — 그대로 둔다).

### ① 실효 판정 하나

- `const autoResOn=()=>(S.star||0)>=1 && S.autoRes;` 를 VIEW 에 두고,
  **`S.autoRes` 를 직접 읽는 자리를 전부 이걸로 바꾼다**: `qClear`(≈2378) · `#spin` 클릭(≈2745) ·
  `autoResolve()` 첫 줄(≈2854) · 250ms 틱(≈2906). 저장값 `S.autoRes` 자체는 건드리지 않는다.
- 결과: 승천 0회에서는 저장값이 true 여도 **자동 정리 0회**, 대기열이 차면 `#spin` 이 「대기열 정리」가 된다(033 ② 그대로).

### ② `#autores` 의 존재

- 승천 0회: `#autores` **표시 안 함**(`display:none`). 클릭 처리기(≈2751)도 `star<1` 이면 아무것도 안 한다.
- 승천 1회 이상: 지금 그대로(켜고 끄는 버튼, `hot` 표시). 저장값 기본이 true 라 **해금 순간 켜진 채로 나타난다.**

### ③ 멈춘 순간을 「할 일」과 「목표」로 — 새 팝업 금지, 글자 둘

- `#autores` 자리(`.qrow` 오른쪽 끝)에, 승천 0회 동안만 **흐린 글자 한 줄**: ko 「자동 정리 · 첫 승천에 열림」 / en 「Auto-sort · unlocks at 1st Ascend」.
  버튼이 아니다(누를 수 없다). 글자 11px 이상(LG1·LG2). 줄이 넘치면 **멈추고 보고.**
- 첫 승천 직후 `#msg` 한 줄: ko 「자동 정리가 열렸다」 / en 「Auto-sort unlocked」.
- `STR` 키 넷(ko/en 각 둘) 추가만 허용(④ 는 별도 허용).

### ④ 테크: 올린 만큼의 **현재 효과**를 글자로, 누르는 즉시 (사용자 판정 2026-10-10 · 같은 지시서로 묶음)

> 「테크에서 별가루로 올렸는데 올린 수치가 텍스트에 반영이 안 된다. 실시간으로 반영되게.」

**지금(실물 확인)**: `renderTech()`(≈2702)의 각 줄은 `t('tech.<k>.nm')` + `t('tech.<k>.d')` + `.lvn`(「L/100」)이다.
`tech.<k>.d` 는 **한 단계당 증가분**(「주기 -0.8%」「+1.5%」)이라 1단계든 50단계든 **같은 글자**다 —
레벨 숫자만 바뀌고 「그래서 지금 얼마나 좋아졌나」는 어디에도 안 나온다. 그것이 사용자가 본 결함이다.

**바꿀 것** — 각 줄의 설명 자리(`.nm i`)를 **「현재 효과 → 다음 단계 효과」**로:

| 키 | 현재 효과의 출처 (CORE 함수·식을 **읽기만**) | 보이는 예 (ko / en) |
|---|---|---|
| `spd` | `CHG_MS()` — 충전 주기 초 | 「주기 6.0초 → 5.95초」 / 「Cycle 6.0s → 5.95s」 |
| `cap` | `CHG_MAX()` — 충전 한도 | 「한도 600 → 630」 / 「Cap 600 → 630」 |
| `sell` | `sellPrice` 의 계수 `1+T('sell')*0.015` | 「판매가 +0% → +1.5%」 |
| `cost` | `upCost` 의 계수 `Math.max(0.5,1-T('cost')*0.005)` | 「강화 비용 -0% → -0.5%」 |
| `gold` | 전투 골드 계수 `1+T('gold')*0.015` | 「골드 +0% → +1.5%」 |
| `align` | `spin()` 의 `T('align')*0.0025` | 「일치 +0% → +0.25%」 |

- `spd`·`cap`·`cost` 는 **CORE 함수를 불러서** 값을 얻는다(다음 단계 값은 `S.tech[k]` 를 잠깐 +1 해서 부르고 즉시 되돌리는 방식 금지 —
  상태를 건드리는 표시는 만들지 않는다. 식을 VIEW 에 옮겨 적어 계산하고, 아래 E1 검사로 CORE 와 일치를 못박는다).
- 상한 도달(`maxed`)이면 「→ 다음」 없이 현재 값만. `spd` 는 1.5초 바닥(`Math.max(1500,…)`)·`cost` 는 -50% 바닥이 있으므로 **바닥에 닿은 뒤에는 「→」 값이 현재와 같다** — 그때도 현재 값만 쓴다.
- **즉시 반영**: 구매 클릭 → 같은 클릭 처리 안에서 그 줄의 레벨·효과·다음 비용·`#dust` 가 바뀐다(지금도 `render()` 를 부르므로 그 경로를 지킨다).
  별가루가 탑·승천으로 바뀐 순간에도 테크 버튼의 활성/비활성이 다음 `render` 를 기다리지 않게 — `renderFast`(250ms)에서 **테크 탭이 열려 있을 때만** 버튼 활성 상태와 `#dust` 를 갱신한다(줄 전체 `innerHTML` 재구성 금지 — renderFast 원칙).
- `STR` 은 `tech.<k>.d` 여섯 키를 **효과 틀 문자열**로 바꾸는 것(ko/en)과 틀에 필요한 키 추가를 허용한다. 각 줄이 380px 에서 두 줄로 넘치면 **멈추고 보고.**

**검사(효과로)**:
- E1 각 키를 0·1·37·100(그리고 `spd` 바닥 직전·직후)으로 놓고 화면 글자의 현재 값이 **CORE 가 실제로 내는 값과 같다**:
  `spd` = `CHG_MS()/1000`, `cap` = `CHG_MAX()`, `sell` = 같은 장비의 `sellPrice` 비(0단계 대비), `cost` = `upCost` 비, `gold` = 웨이브 골드 식의 비, `align` = 계수.
  **변이**: VIEW 의 계수 하나를 바꾼 빌드(예: sell 0.015→0.02) → E1 이 운다.
- E2 별가루가 충분한 판에서 버튼 클릭 → **같은 프레임 안에** 그 줄의 레벨·현재 효과 글자·비용·`#dust` 가 바뀐다(다음 틱 대기 아님).
- E3 테크 탭을 연 채로 탑 보상으로 별가루가 비용을 넘는 순간 → 250ms 안에 버튼 활성.

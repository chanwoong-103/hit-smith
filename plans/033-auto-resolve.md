# 033 — 자동이면 대기열을 알아서 정리한다 · 무거운 변경 · 담당: 코딩 세션

상태: **대기 — 착수 가능** (031·032 검증 통과 2026-09-28, 락 비어 있음).
028(CrazyGames 제출)보다 먼저.

## 왜 — 방치하면 5.3초 만에 게임이 선다

032 검증 실측: 새 세이브·자동 켬·손 안 댐 → **5.3초** 만에 대기열 10칸이 차서
자동 제련이 멈춘다. 충전 600 은 거의 그대로 남는다. 새로 온 사람이 자동을 켜고
지켜보면 **5초 만에 화면이 멈춘다** — 사용자가 걱정한 「금방 이탈」의 실체다.

그리고 **`days.js` 는 처음부터 자동 정리를 전제로 쟀다.** `doSpins()` 는 뽑을 때마다
`power()` 로 비교해 더 좋으면 장착하고(이전 것은 판매), 아니면 판다. 032 의 시작 충전과
같은 구조다 — **곡선은 「알아서 도는 게임」을 전제로 측정됐고, 게임만 5초마다 사람 손을
요구하고 있었다.**

## 사용자 판정 (2026-09-28) — 「둘 다」 + 「그 버튼도 켜고 끄는 버튼으로」

1. **자동 정리는 대기열 줄 옆에 있는 켜고 끄는 버튼 `#autores` 「정리」다.**
   「자동」(`#auto`)과 **같은 켜짐 표시(`hot`)**. 둘은 서로 독립이다 —
   손으로 제련하면서 정리만 맡길 수도 있고, 자동 제련하면서 정리는 직접 할 수도 있다.
2. **정리가 켜져 있으면**, 대기열이 가득 찼을 때 알아서 정리한다.
3. **정리가 꺼져 있으면**, 대기열이 가득 찼을 때 제련 버튼이 「대기열 정리」로 바뀐다.
4. **기본값은 켜짐** — 새 세이브와 기존 세이브 모두(값이 없으면 켜짐). 방치하는 사람이
   5초 만에 멈추지 않는 것이 이 지시서의 목적이다. 끄는 사람은 원칙 4 ③ 결정을 되찾는다.

## 변경할 것

### ① 자동 정리 (`#autores` 켬 + 대기열 가득)

- 스핀이 대기열 때문에 막히는 순간, **대기열 맨 앞 하나**를 정리한다:
  - 장착하면 `power()` 가 **오르면** → 장착. 밀려난 이전 장비는 **판매**.
  - 아니면 → **판매**.
- **수동 버튼이 부르는 바로 그 함수를 부를 것**(장착·판매 경로). 새 판정식·새 보상식 금지.
  골드·토큰·천장·옵션 등 **보상이 수동 판매와 한 푼도 다르면 안 된다.**
- 비교는 **`power()` 하나**. `days.js` 가 쓰는 것과 같은 함수다. 새 점수를 만들지 말 것.
- **비교 팝업(`#cmp`)이 열려 있으면 자동 정리를 멈춘다** — 사람이 고르는 중이다.
- 자동 판매 체크(`#asell`)는 지금처럼 대기열 앞에서 먼저 걸러진다. 순서 그대로.
- 한 틱에 **하나씩만** 정리한다(연출·판정문이 한꺼번에 쏟아지지 않게).
- 정리할 때 `#msg` 에 한 줄(예: 「자동 정리 — 장갑 3등급 장착」/「… 판매」). 새 패널·새 팝업 금지.

### ② 대기열 정리 버튼 (`#autores` 끔 + 대기열 가득)

- 제련 버튼(`#spin`)의 글자가 「제련 N」 → **「대기열 정리」** 로 바뀌고, 누르면
  **비교 팝업을 연다**(기존 `openCmp`). 한 칸이라도 비면 원래대로.
- 버튼 **자리·크기·색은 그대로** — `TB8`·`AD6` 가 보는 좌표가 움직이면 안 된다.

### ①-b 버튼과 상태

- **자리 (사용자 판정 2026-09-28): 대기열 줄 옆.** 제련 줄 아래의
  「대기 N/10 · 릴을 눌러 고정」 줄(`#qn`·`#qm` 이 든 줄)에 붙인다. 글자 「정리」.
  **제련 줄(`#spin`·`#auto`)은 한 픽셀도 안 바뀐다** — 그래서 `TB8`·`AD6` 좌표도 그대로다.
  대기열이 차는 것을 보여 주는 숫자 바로 옆이라 「무엇을 정리하는지」가 한눈에 읽힌다.
  작은 버튼이지만 **글자 11px 이상**(`LG1`/`LG2`)과 손가락으로 누를 수 있는 높이를 지킬 것.
  한 줄에 안 들어가 줄이 넘치면 **멈추고 보고**.
- 상태는 `S.autoRes`(불리언) — `S.auto` 와 같은 자리에 저장된다.
  ⚠ **이것은 CORE 기본 상태에 필드 하나를 더하는 일이다.** 허용한다 — 기본 상태 한 줄과
  불러오기 보정 한 줄(`S.autoRes = S.autoRes ?? true`, **0·false 를 덮지 않게** `??`).
  그 두 줄 밖의 CORE 는 여전히 금지. `days.js` 기본 출력 `81a6288…` 은 그대로여야 한다.
- 켜짐 표시는 `#auto` 가 쓰는 것과 **같은 방식**(`className='hot'`). 새 색·새 아이콘 금지.

### ③ 031 검증 제안 ① — 주석의 화살표

소스 주석(화로 높이 절)과 031 §4 의 「화로 118→100px」 방향이 **거꾸로** 적혀 있다(현행
118px, 100·92px 이 031 전 값). 다음 세션이 `#hearth{min-height:118px}` 을 걷어낼 수 있다.
**주석만** 바로잡을 것.

## 설계 문서 갱신 — 원칙이 바뀌는 것이 아니다

- 원칙 8(「판매만이 대기열을 줄인다」)은 **그대로다** — 자동 정리도 판다.
- 원칙 4 ③(「교체하나 파나」)은 **자동을 끄면 그대로 사람의 결정**이다. 자동은 그 결정을
  맡기는 스위치다. DESIGN.md 의 결정 목록 옆에 이 한 줄을 적을 것.
- DESIGN.md 수동 체크리스트 「대기 가득 → 스핀 정지 → 정리 후 재개」를 **자동 켬/끔 두 줄로**.

## 검사 — 이 결함은 「시간이 흐르면 무슨 일이 일어나는가」다

CLAUDE.md 「검사는 화면이 무엇을 그리는지는 보지만 무슨 일이 일어나는지는 안 본다」의
자리다. 검증 세션과 합의할 것 — 코딩 세션은 실측을 남긴다:

- **방치 실측**: 새 세이브·자동 켬·손 안 댐 → 충전이 1 미만이 될 때까지 걸린 시간과
  그동안 **스핀이 대기열 때문에 막힌 횟수(0 이어야 한다)**.
- **전투력 단조**: 방치 동안 `power()` 가 한 번도 내려가지 않는다.
- **보상 동일**: 같은 아이템을 자동 정리로 팔 때와 수동으로 팔 때 골드·토큰 증가가 같다.
- **팝업 존중**: `#cmp` 가 열린 동안 자동 정리 0회.
- **변이 둘**: ㉮ 더 나쁜 장비를 장착하는 빌드 → 전투력 단조 검사가 운다.
  ㉯ 팝업이 열려도 정리하는 빌드 → 팝업 존중 검사가 운다.
- 정리 끔 + 대기열 가득 → `#spin` 글자 「대기열 정리」, 누르면 `#cmp` 열림.
- **정리 끔 + 자동 켬** → 지금처럼 가득 차면 멈춘다(끄면 옛 동작 그대로인지).
- **기본값**: 새 세이브·`autoRes` 없는 옛 세이브 둘 다 켜짐. `false` 로 저장된 세이브는 꺼짐 유지.
- `TB8` 에 `#autores` 를 더할 것(9크기에서 굴리지 않고 보이는가).

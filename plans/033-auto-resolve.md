# 033 — 자동이면 대기열을 알아서 정리한다 · 무거운 변경 · 담당: 코딩 세션

상태: **구현 완료 — 검증 대기** (코딩 세션, 2026-09-28) — `src/forge.html` **락 해제**.
028(CrazyGames 제출)보다 먼저.

## 왜 — 방치하면 5.3초 만에 게임이 선다

032 검증 실측: 새 세이브·자동 켬·손 안 댐 → **5.3초** 만에 대기열 10칸이 차서
자동 제련이 멈춘다. 충전 600 은 거의 그대로 남는다. 새로 온 사람이 자동을 켜고
지켜보면 **5초 만에 화면이 멈춘다** — 사용자가 걱정한 「금방 이탈」의 실체다.

그리고 **`days.js` 는 처음부터 자동 정리를 전제로 쟀다.** `doSpins()` 는 뽑을 때마다
`power()` 로 비교해 더 좋으면 장착하고(이전 것은 판매), 아니면 판다. 032 의 시작 충전과
같은 구조다 — **곡선은 「알아서 도는 게임」을 전제로 측정됐고, 게임만 5초마다 사람 손을
요구하고 있었다.**

## 사용자 판정 (2026-09-28) — 「둘 다」 + 「그 버튼도 켜고 끄는 버튼으로」

1. **자동 정리는 대기열 줄 옆에 있는 켜고 끄는 버튼 `#autores` 「정리」다.**
   「자동」(`#auto`)과 **같은 켜짐 표시(`hot`)**. 둘은 서로 독립이다 —
   손으로 제련하면서 정리만 맡길 수도 있고, 자동 제련하면서 정리는 직접 할 수도 있다.
2. **정리가 켜져 있으면**, 대기열이 가득 찼을 때 알아서 정리한다.
3. **정리가 꺼져 있으면**, 대기열이 가득 찼을 때 제련 버튼이 「대기열 정리」로 바뀐다.
4. **기본값은 켜짐** — 새 세이브와 기존 세이브 모두(값이 없으면 켜짐). 방치하는 사람이
   5초 만에 멈추지 않는 것이 이 지시서의 목적이다. 끄는 사람은 원칙 4 ③ 결정을 되찾는다.

## 변경할 것

### ① 자동 정리 (`#autores` 켬 + 대기열 가득)

- 스핀이 대기열 때문에 막히는 순간, **대기열 맨 앞 하나**를 정리한다:
  - 장착하면 `power()` 가 **오르면** → 장착. 밀려난 이전 장비는 **판매**.
  - 아니면 → **판매**.
- **수동 버튼이 부르는 바로 그 함수를 부를 것**(장착·판매 경로). 새 판정식·새 보상식 금지.
  골드·토큰·천장·옵션 등 **보상이 수동 판매와 한 푼도 다르면 안 된다.**
- 비교는 **`power()` 하나**. `days.js` 가 쓰는 것과 같은 함수다. 새 점수를 만들지 말 것.
- **비교 팝업(`#cmp`)이 열려 있으면 자동 정리를 멈춘다** — 사람이 고르는 중이다.
- 자동 판매 체크(`#asell`)는 지금처럼 대기열 앞에서 먼저 걸러진다. 순서 그대로.
- 한 틱에 **하나씩만** 정리한다(연출·판정문이 한꺼번에 쏟아지지 않게).
- 정리할 때 `#msg` 에 한 줄(예: 「자동 정리 — 장갑 3등급 장착」/「… 판매」). 새 패널·새 팝업 금지.

### ② 대기열 정리 버튼 (`#autores` 끔 + 대기열 가득)

- 제련 버튼(`#spin`)의 글자가 「제련 N」 → **「대기열 정리」** 로 바뀌고, 누르면
  **비교 팝업을 연다**(기존 `openCmp`). 한 칸이라도 비면 원래대로.
- 버튼 **자리·크기·색은 그대로** — `TB8`·`AD6` 가 보는 좌표가 움직이면 안 된다.

### ①-b 버튼과 상태

- **자리 (사용자 판정 2026-09-28): 대기열 줄 옆.** 제련 줄 아래의
  「대기 N/10 · 릴을 눌러 고정」 줄(`#qn`·`#qm` 이 든 줄)에 붙인다. 글자 「정리」.
  **제련 줄(`#spin`·`#auto`)은 한 픽셀도 안 바뀐다** — 그래서 `TB8`·`AD6` 좌표도 그대로다.
  대기열이 차는 것을 보여 주는 숫자 바로 옆이라 「무엇을 정리하는지」가 한눈에 읽힌다.
  작은 버튼이지만 **글자 11px 이상**(`LG1`/`LG2`)과 손가락으로 누를 수 있는 높이를 지킬 것.
  한 줄에 안 들어가 줄이 넘치면 **멈추고 보고**.
- 상태는 `S.autoRes`(불리언) — `S.auto` 와 같은 자리에 저장된다.
  ⚠ **이것은 CORE 기본 상태에 필드 하나를 더하는 일이다.** 허용한다 — 기본 상태 한 줄과

  그 두 줄 밖의 CORE 는 여전히 금지. `days.js` 기본 출력 `81a6288…` 은 그대로여야 한다.
- 켜짐 표시는 `#auto` 가 쓰는 것과 **같은 방식**(`className='hot'`). 새 색·새 아이콘 금지.

### 판정 ⓑ — `resolve()` 끝의 `newWave();` 삭제 (CORE 한 줄)

메운 것이고, 검사로 세우는 건 제안 ⑸에 올렸다.

  `newWave()` 를 부르므로, `foeHP` 를 `foeMax` 의 30~80% 로 깎아 두고 그 구간에서만 잰다.
- **되감김만 보면 반쪽**이라 실제 시간 2.4초를 흘려 **적 체력이 더 줄었는지**도 본다.
- **수동(`resolve('sell')`)과 자동(`autoResolve()`) 두 벌**을 다 본다 — CORE 는 한 줄이라
  둘이 같이 움직인다.

```
PASS  적 509/736 → 509 (웨이브 17→17 · 내 체력 1027→1027) → 2.4초 뒤 적 244 · 웨이브 19   [현행]
FAIL  적 509/736 → 736 **되감겼다(가득)** · 내 체력 1027 → 1040 **공짜로 찼다**            [㉰ 변이]
```

**㉰ 변이에서 우는 것은 `RS1` 하나뿐이고, 나머지 121 항목은 전부 PASS 다.**
이것이 033 제안 ⑸ 의 증명이다 — `newWave();` 가 있든 없든 **기존 검사는 눈을 감고 있었다.**
⚠ 이 변이는 **033 이 적은 「장착의 공짜 회복이 사라졌다」(제안 ⑹)도 그대로 보여 준다** —
`newWave();` 를 되돌리면 내 체력이 1027 → 1040·1082 로 찬다. `RS1` 은 그 회복도 FAIL 로 센다.

#### ⑦ `TB8_SKIPS` — 두 칸이 이름과 이유를 **매번** 찍는가

**찍는다.** 판정문 조립이 합·불 삼항 **밖**에 붙어 있어 구조적으로 양쪽에 다 나오고,
㉱ 변이로 실제 **FAIL 판정문에서도** 둘 다 나오는 것을 확인했다:

```
· **제외 2칸(결함이 아니라 설계):** **380×820 세로/배너/제련** — 027 판정 ① …
  /  **380×820 세로/평범/정리** — 033 판정 ⓐ — 이 줄(「대기 N/10」)은 033 전에도 …
```

`TB8` 도 43칸 = 9크기 × (평범 3 + 배너 2) − 예외 2칸으로 맞다.

#### ⑧ 031 검증이 심은 오류를 하나 잡아 고쳤다 — `GR1`·`LG2` 의 부위 id

`GR1`·`LG2` 가 최악 조건을 심을 때 쓴 부위 id 가 `'hand'·'leg'·'acc'` 였다 —
**`PARTS` 에 없는 id** 다(진짜는 `legs`·`hands`·`feet`). 그래서 **여섯 칸 중 셋이 빈
칸**으로 그려졌고, `GR1` 은 `.slot` 개수(빈 칸 포함 항상 6)와 **첫 칸의 `.gd`** 만 봐서
그것을 못 잡았다. 031 검증 세션이 심은 오류이고, 033 검증에서 다른 검사를 짜다 터져 나왔다.

- 부위 id 를 고치고, **칸마다** `.gd`·`.op` 를 확인하며 `.slot:not(.empty)` 가 **6개**인지
  단정하도록 `GR1` 을 조였다.
- **고친 뒤에도 9크기 전부 0px PASS** 다 — 3열 격자라 한 줄만 채워도 열 폭 압력은 같았고,
  031 검증의 여백-되돌림 변이가 §3 의 수치(11·14.1·23.4px)를 그대로 낸 것도 그 때문이다.
  **판정은 안 뒤집히지만 검사가 반쪽이었던 것은 맞다.**

#### ⑨ 031 검증 제안 ① — 주석 정정 확인

`#hearth{min-height:118px}` 절의 화살표가 바로잡혔고, 033 이 새로 적은 설명
(「눌리는 것은 화로가 아니라 패널 전체다 — `#forge` 297 → 279px(821×462)·267px(800×450)」)은
**내 실측과 정확히 같다.**

## 제안 (구현하지 말고 여기에 적을 것)

1. **`#spin` 의 「제련」과 숫자 사이 공백이 사라졌다.** `제련 <span id="chg">` 가
   `<span id="spinlbl">제련</span><span id="chg">` 로 쪼개지면서 그 사이의 **띄어쓰기
   한 칸이 없어졌다** — 아홉 크기 전부에서 버튼 글자가 **「제련600」**이다(이전 빌드는
   「제련 600」). 033 구현 결과 문서 자신도 「제련 600」이라고 적고 있다. `#spinlbl` 에
   `제련 ` 을 넣거나 `#spinlbl{margin-right:.35em}` 한 줄이면 된다.
2. **「제련 줄은 한 픽셀도 안 바뀐다」는 두 크기에서 참이 아니다.** x·너비·높이는 아홉
   크기 전부 같지만 **y 가 움직인다**: 821×462 `y 331.5 → 326.1` · 800×450 `y 325.4 → 320.1`
   (−5.3px). 나머지 일곱 크기는 그대로다. 대기열 줄이 14px 짜리 글자 줄에서 28px 짜리
   버튼 줄이 되면서, `max-height:100%` 에 걸린 짧은 가로 창에서 가운데 정렬이 위로
   민 것이다. `TB8`·`AD6` 는 좌표가 아니라 «보이는가/맨 위가 무엇인가»를 보므로 둘 다
   PASS 다 — **판정에는 영향이 없고, 문장이 과한 것이다.**
3. **⚠ 800×450 의 여유가 거의 다 떨어졌다.** `#forge` 안쪽 여백이
   **9/7px → 4/2px** 로 줄었다(821×462 도 15/13 → 10/8). 031 검증 제안 ②가 「내용이
   8px 더 늘면 테두리에 닿는다」고 적어 둔 그 여유를 033 이 6px 더 썼다. **아래로 남은
   여유가 2px 다** — 이 칸에 한 줄이라도 더 붙이면 CrazyGames 모바일 크기가 먼저 깨진다.
   이 여유를 보는 검사는 아직 없다(`GR1` 은 가로, `TB8` 은 보임만 본다).
4. **033 제안 ⑴ 의 나머지(⑴ 막힌 스핀 0 · ⑵ 전투력 단조 · ⑶ 팝업 존중 · ⑷ 보상 동일)는
   아직 검사가 아니다.** 이번에도 임시 계측이 냈다. ⑷ 는 1초면 끝나고 변이도 잘 무므로
   **checklist 본체에 바로 세울 수 있다**(같은 아이템을 수동·자동으로 처리해 골드·토큰
   델타를 맞대는 한 항목). ⑶ 도 3초면 된다. ⑴⑵ 는 분 단위라 `soak.js` 결이 맞다 —
   다만 **압력을 유지해야 한다**: 이번에 「팝업 존중」을 처음 쟀을 때 대기열이 가득이

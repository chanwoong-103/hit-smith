# 001 — 웨이브 연출 (지시서 양식 예시 겸 첫 작업)

상태: 완료 (검증 통과 · 2026-08-29)

## 목표
체력바 두 줄뿐인 전투 패널에, 적 무리가 보이고 깎이는 최소 연출을 넣는다.

## 변경할 것
- 전투 패널에 적 무리 표시: 웨이브당 적 5~9개를 작은 DOM 블록으로.
  체력 비율에 따라 하나씩 소멸 (전체 체력 / 개체 수 나눗셈이면 충분,
  개체별 체력 시뮬레이션 금지).
- 근접(▪붉은 계열)/원거리(▫푸른 계열)/혼합이 한눈에 구분되게.
- 처치 순간 1회성 CSS 애니메이션 (transform+opacity만, 파티클 라이브러리 금지).
- 플레이어 피격·흡혈 회복이 체력바에 미세하게 표현되면 가산점 (선택).

## 바꾸지 말 것
- tick() 전투 수식 일절 (연출은 표시 계층에만).
- renderFast 원칙: 틱당 innerHTML 재구성 금지. 적 블록은 웨이브 시작 시
  1회 생성, 틱에는 style 토글만.
- 단일 파일, 무의존.

## 완료 조건
- node tools/smoke.js 전 항목 통과, 콘솔 self-check 무오류.
- 수치 미변경이므로 days.js 는 실행만 하고 곡선 동일함을 확인.
- 모바일 폭(~380px)에서 레이아웃 안 깨짐.
- DESIGN.md 수동 체크리스트 전 항목 유지.

## 제안 (코딩 세션이 발견한 것을 여기에 적고 구현하지 말 것)
- 마지막 개체는 웨이브 클리어와 동시에 newWave()가 무리를 다시 그려서 소멸
  애니메이션이 잘린다. 전환에 0.3초 정도 여유를 두면 마무리가 보이겠지만
  틱 루프 타이밍을 건드려야 해서 손대지 않았다. 계획 세션 판단 요망.
- #hpghost(늦게 따라오는 붉은 띠) 방식은 적 체력바 #bar 에도 그대로 붙는다.
  적이 여러 번 맞는 감각이 필요하면 지시서 하나로 추가 가능.
- 적 개체 수는 웨이브별 고정식(5+(wave*7)%5)이라 층 감각이 없다. 보스 웨이브
  같은 구분을 개체 수로 표현할 수 있으나 새 시스템이므로 구현하지 않음.

## 구현 메모 (코딩 세션)
- 추가: `#mob` 컨테이너 + `.foe` 블록, `#hpghost`, `.foe.dead` 키프레임.
- `buildFoes()` 는 newWave() 에서만 innerHTML 을 쓰고, 틱에서는 `drawFoes()` 가
  상태가 바뀐 개체만 class 토글 → 처치 애니메이션이 개체당 1회만 재생된다.
- tick() 의 전투 수식·상태·저장은 손대지 않았다. 추가된 것은 표시용
  `hp0`(직전 체력) 캡처와 표시 갱신 호출뿐.
- self-check 에 적 개체 수 범위(5~9)·분포·블록 수 일치 검사 3종 추가.
- days.js 는 시드가 없어 실행마다 값이 흔들린다(원본도 동일 확인). 목표 도달일
  표는 원본과 같은 대역: w100 12~14일 / w150 20~22일 / w200 26~29일,
  접속 시간 10~120분 간 차이 없음.

### 발견 (001 책임 아님 — 계획 세션이 별도 지시서로 처리 요망)

**발견 1 · 세이브가 있는 상태로 로드하면 self-check 가 실패한다 (경미, 선행 결함)**
자체 점검이 "새 게임"을 전제로 짜여 있어서, 저장된 진행이 있으면 다음 assert 가
콘솔에 뜬다. 001이 추가한 적 무리 검사 3종은 전부 정상 통과한다.

| 세이브 상태 | 실패하는 assert |
|---|---|
| 제련 6 / ★0 | `초기 상한이 5가 아님` |
| 제련 2 / ★1 | + `초기 대기창이 10칸이 아님` |
| 제련 28 / ★3 | + `릴 수 오류` |

- `초기 상한이 5가 아님` / `초기 대기창이 10칸이 아님` — `cap()===5`, `qmax()===10`
  을 현재 S 로 검사한다. 저장값을 백업/복원한 뒤 검사하거나(다른 assert 들은
  이미 그렇게 한다) 고정값으로 계산해야 한다.
- `릴 수 오류` — `REELS()===3+S.star && REELS()<=5` 는 ★2까지만 참이다.
  릴이 5에서 멈추는 건 의도된 설계(BALANCE.md 백로그)이므로 검사식이 틀렸다.
  `REELS()===Math.min(5,3+S.star)` 여야 한다.
- CLAUDE.md 완료 조건이 "콘솔 self-check 무오류"이므로, 이 상태로 두면 앞으로
  모든 코딩·검증 세션이 **복귀 유저 환경에서는 항상 실패를 본다.** 우선 처리 권장.

**발견 2 · days.js 합격표의 폭이 시뮬 자체 노이즈보다 좁다**
BALANCE.md 목표 페이싱 표(30분+ w200 27~29일)를 3회 실행 중 2회가 벗어난다
(30일, 31일). 수치를 안 바꿨는데도 그렇다 = 표가 아니라 시드 부재가 원인.
선택지: ① days.js 에 고정 시드 PRNG 를 넣어 결정적으로 만든다(권장, 검증 도구가
검증 가능해진다) ② BALANCE.md 표의 폭을 실측 노이즈에 맞춰 넓힌다.
현행대로 두면 무관한 작업이 페이싱 회귀로 오판되어 반려될 수 있다.

**발견 3 · 첫 접속 화면에 무한의 층 티켓(🎟)·테크트리가 그대로 보인다**
원칙 7 "첫 3분은 데일리·타이머 노출 없이 순수 스핀만" 과 어긋난다. 티켓은
날짜 리셋 자원이므로 사실상 데일리 노출이다. 001 범위 밖이라 손대지 않았다.

### 검증 방법 메모
수동 체크리스트를 Playwright(headless Chromium, 380×820)로 자동 재현했다.
스크립트는 `devtools/checklist.js` 로 커밋했다 (CLAUDE.md devtools/ 규정 신설,
2026-08-29). node_modules·락파일은 커밋하지 않았고, playwright 는 저장소 밖
(전역 또는 `PW_HOME`)에서 찾아 쓴다. 설치·실행법은 파일 상단 주석에 있다.

- `node devtools/checklist.js` → 56항목, 실패 0건이면 exit 0.
- **완료 조건 아님.** 판정은 tools/ + 사람이 하는 수동 체크리스트로 한다.
- 발견 1의 self-check assert 3종은 `KNOWN` 배열에 등록해 WARN 으로만 뜬다.
  고쳐지면 그 배열에서 빼면 다시 FAIL 로 감지된다.

### 1. 스프라이트 18장
- 부위 6(무기·모자·상의·하의·장갑·신발) × 실루엣 3단계 = 18장.
  단계 구분은 002가 정한 그대로: 1~5 조악 / 6~10 정제 / 11~15 장식.
- **코드 안에 압축된 문자열로 넣는다** — 행마다 팔레트 인덱스 문자열 같은

- 픽셀 크기는 하나로 통일한다(예: 16×16 또는 24×24). 부위마다 다른 해상도를
  쓰지 말 것 — 나중에 스케일이 어긋난다.

### 2. 등급 15종 = 팔레트 스왑 공식
- 스프라이트는 **팔레트 인덱스**로 그린다(예: 외곽선/본체 어두움/본체 밝음/

### 3. 픽셀 렌더링 품질 (여기서 실패하면 전부 무의미하다)

### 4. 사용처 전환

## 구현 결과 (코딩 세션 2026-08-30)

### 0. 【선행】 배경 재그리기 제거 — 프레임 비용 전후

**원인**: 008 의 뒤 겹은 매 프레임 Graphics 를 통째로 다시 렌더한다. 배경 잔광만
화면폭 1.7배짜리 타원 **26장**이라, 프레임마다 화면을 26번 덧칠하는 셈이다.
지시서가 지목한 대로 두 번째 캔버스는 주인이 아니었다 — 같은 스크립트로 재확인:
`#fx` 를 통째로 파괴해도 380폭 0.1ms / 1280폭 16.6ms 밖에 안 준다.

**고침**: 정적인 것을 `RenderTexture` 에 구워 프레임당 사각형 두 장으로 만든다.
- `rtBg` — 화면 크기에만 의존. **리사이즈 때만** 다시 굽는다.
- `rtPanel` — 가운데 패널 묶음(패널 바탕·화로 창·불빛·모루). **크기가 바뀔 때만**
  다시 굽고, 스크롤로 위치만 바뀌면 `setPosition` 만 한다.

RT 로 구우면 지오메트리 마스크가 같이 안 구워져서, 화로 불빛 클리핑은 마스크
대신 타원 크기를 창 안으로 묶는 방식으로 바꿨다.

**측정 방법** (전후 동일): 같은 컨테이너·같은 스크립트에서 rAF 간격 70프레임을
받아 앞 10프레임(예열)을 버리고 **중앙값**을 쓴다. 헤드리스는 소프트웨어 GL 이라
지시서 지침대로 **절대값이 아니라 상대값**으로 읽는다.

| 폭 | 008 (전) | 009 (후) | |
|---|---|---|---|
| 380 | **116.7 ms** | **16.7 ms** | 7.0배 · 60fps 상한에 붙음 |
| 1280 | **283.3 ms** | **33.3 ms** | 8.5배 · 30fps |

(009 지시서가 인용한 008 실측 124/279ms 와 같은 자리다 — 재현됐다.)

재굽기가 정말 안 도는지는 `__view.perf` 로 확인한다. 부팅 직후
`{bgBakes:2, panelBakes:2, moves:0}` → **3초 방치 후에도 그대로** →
스크롤 300px 후 `moves:1` (재굽기 0). 스크롤해도 RT 위치와 DOM 좌표가 1px 안에서
일치한다.

### 1. 스프라이트 18장

부위 6 × 실루엣 3단계 = **정확히 18장**, 전부 16×16.
한 장은 16행을 이어 붙인 **256자 문자열**이고, 문자는 `.1234` 다섯 개뿐 —
**색이 아니라 팔레트 인덱스**(투명/외곽선/본체어둠/본체밝음/하이라이트)다.
외부 파일 없음, base64 PNG 없음. 데이터 총량 **4,608 B**(SPR 블록 전체 4,853 B).

실루엣 단계 경계는 002 가 정한 그대로 `TIER()`: 1~5 조악 / 6~10 정제 / 11~15 장식.

### 2. 등급 15종 = 팔레트 스왑 공식

등급색 한 개에서 4단계를 뽑는 **공식**이다. 등급마다 손으로 고른 색표는 없다.

```
외곽선   = 등급색 × 0.30
본체어둠 = 등급색 × 0.62
본체밝음 = 등급색            (그대로)
하이라이트 = mix(등급색, 백열 #FFD9A0, 0.55)
```

등급색은 런타임에 `--g1~--g15` 를 읽어 쓴다 — **값을 복사해 두지 않았으므로**
CSS 토큰이 바뀌면 스프라이트도 따라간다. 실측 표본:

| 등급 | 단계 | --g | 외곽선 | 본체밝음 | 본체밝음 = 등급색? |
|---|---|---|---|---|---|
| 1 | 1 | #6b7683 | 32,35,39 | 107,118,131 | ✓ |
| 5 | 1 | #c06fb8 | 58,33,55 | 192,111,184 | ✓ |
| 6 | 2 | #d4903f | 64,43,19 | 212,144,63 | ✓ |
| 10 | 2 | #ff3d7f | — | — | ✓ |
| 11 | 3 | #4dd0e1 | 23,62,68 | 77,208,225 | ✓ |
| 15 | 3 | #ffffff | 77,77,77 | 255,255,255 | ✓ |

공식성 확인: 같은 등급 두 번 → 동일 / 다른 등급 → 다름 / 다른 단계 → 다름.
`--g1~--g15` 는 한 글자도 안 건드렸다 (온도 램프는 ART-DIRECTION 에서 기각된 안).

### 3. 픽셀 렌더링 품질 — 확대를 PNG 에 구워 넣었다

**첫 구현은 CSS 로 키웠는데, 화면의 스프라이트 10개가 전부 소수점 좌표에
앉아 있었다** (flex 안이라 불가피하다). 그 상태에서 CSS 로 2배를 주면 원본 픽셀이
2px·3px 로 들쭉날쭉 잘린다 — `image-rendering:pixelated` 로도 못 막는다.

그래서 **확대를 굽는 쪽으로 바꿨다**: 원본 1픽셀을 `scale×scale` 블록으로 직접
찍어 32px/48px PNG 를 만든다. 화면에는 **1:1**(자연 크기 = 표시 크기)로 놓이므로
위치가 소수여도 픽셀 폭이 균일하다. 네 크기 전부 `일대일: true` 로 확인했다.

배율은 **정수만**: 기본 2배(32px), 릴 칸은 3배(48px), 좁은 화면(≤415px)은 2배.
좁은 화면에서 48px 이미지를 CSS 로 32px 로 줄이면 정수 배율이 깨지므로,
**줄이지 않고 처음부터 그 배율로 굽는다.**

확대 스크린샷(릴 아이콘 8배 확대)에서 픽셀 블록이 3×3 로 균일하고 가장자리
번짐이 없다 — 380폭(2배)·1280폭(3배) 둘 다.

   때만 깨우면 방치 중 배경 비용이 0 이 된다. 009 범위 밖이라 안 했다.
3. **SVG 심볼 18개를 아직 못 지운다.** `icoSVG()` 가 node harness 폴백으로 살아
   있어서다. 폴백을 없애려면 harness 에 캔버스 목을 넣거나, 폴백을 "빈 칸"으로
   받아들이기로 정해야 한다. 지우면 약 4KB 가 준다.
4. **t3(11~15) 실루엣이 장식이라기보다 뿔 달린 생물처럼 읽힌다.** 머리·상의가
   특히 그렇다. 형태 자체는 18장 범위 안에서 다시 그릴 수 있으니, 디자인 세션
   지시서로 "t3 장식 방향 재드로잉"을 한 번 잡는 편이 좋겠다. 시스템은 그대로
   두고 문자열 6줄만 바뀐다.
5. ART-DIRECTION 의 **숫자 비트맵 글리프는 010 몫**으로 남아 있다. 스프라이트
   파이프라인(문자열 → 팔레트 → PNG)을 그대로 재사용할 수 있으니, 010 은
   `SPR` 옆에 `GLYPH` 를 하나 더 두면 된다.

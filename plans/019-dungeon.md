### ① §3 죽은 분기 — 지우지 않고 죽었음을 명시

`foeOutline()` 위 주석에 근거를 박았다: 땅은 `normRGB` + `DEPTH[2]=0.32` 로
**상대휘도 0.084 에서 포화**하고 `OUT_LUM` 은 0.36 이라 밝은 땅 분기는 **도달
불가**다. 코드는 그대로 두고 분기 줄에 「죽은 분기」 표시만 달았다.
`DEPTH`·`normRGB`·`OUT_LUM` 은 한 글자도 건드리지 않았고, **던전 띠도 무대와
같은 `stagePalette(seg,2)` 를 쓴다** — 그래서 던전을 붙여도 땅 명도가 안 움직인다.
실측(구간별 땅 상대휘도): **0.0570 / 0.0644 / 0.0653** — 전부 0.36 아래.
`MC1`·`MC2` 는 손대지 않았고 값도 그대로다(몹 4.21/4.08/4.02 · 용사 3.59/3.36/3.33).

### ② §2 유휴 비용 — 둘로 갈라 각각 답한다

**(가) `document.hidden` ⇒ duty 0%** (완료 조건 ≤ 2%).
- `hidden()` 한 술어를 세 자리에 건다: 두 겹의 프레임 머리(그 자리에서 재운다),
  `canvasWake()`(**깨우는 길 자체를 막는다** — 밀린 창을 쌓아 두지도 않는다),
  `hitFx()`·`__foeDie()`·`__fxBurst()`(연출을 시작조차 않는다).
- 숨는 순간 **도는 것을 버린다**: 이동은 끝점으로 스냅, 공격·소멸·불티·바운스는
  버리고 두 겹을 재운다. 시간만 얼리면 돌아왔을 때 몇 분 전 동작이 재생된다.
- 돌아오면 `visibilitychange` 에서 `canvasWake(600)` 한 번. 리스너는 `document`
  에 건다(사건이 나는 자리). **CORE 의 저장용 리스너는 건드리지 않았다.**
- 실측 30초: **뒤 겹 0% · 앞 겹 0% · sleeping=true · 건너뛴 연출 19건**.
  ⚠ 측정 방법: headless 는 탭을 진짜로 숨길 수 없어(bringToFront 로는 둘 다
  visible, CDP `Page.setWebLifecycleState` 는 hidden 을 모른다) `document.hidden`
  을 참으로 바꾸고 `visibilitychange` 를 쏘는 식으로 브라우저를 흉내 냈다.
  **이 편이 더 엄한 검사다** — 브라우저의 rAF 감속이 안 걸리므로 구현이 스스로
  재우지 못하면 수치가 그대로 남는다. 변이 확인: `hidden()` 을 `()=>false` 로
  바꾼 빌드는 같은 검사에서 **11.6% / 12.0% 로 FAIL** 했다(= 감속 덕이 아니다).

**(나) 탭이 보일 때 — 내리지 못했다. 내역은 이렇다.**
같은 기계에서 연달아 60초씩:

| | 뒤 겹 | 앞 겹 | 사건 | 내역 |
|---|---|---|---|---|
| 018 | 11.43% | 11.43% | 소멸 16회(16마리) · 이동 0 · 정렬 0 | 소멸 6.4s = 10.7% |
| 019 | 11.60% | 11.60% | 소멸 16회(16마리) · 이동 0 · 정렬 0 | 소멸 6.4s = 10.7% |

**유휴 duty 는 사실상 전부 소멸 깨움 창이다.** 창 하나가 `DIE_MS+80 = 400ms`
이고 방치 중 몹은 평균 3.8초에 한 마리씩 빠지므로 400/3800 ≈ 10.7% — 예측과
실측이 0.2%p 안에서 맞는다(이동·정렬은 유휴에 0회). 즉 **남은 비용은 "320ms
짜리 소멸 연출을 보여 주는 값" 그 자체**이고, 내리는 길은 `DIE_MS` 를 깎거나
소멸을 끄는 것뿐이라 이번에는 손대지 않았다(§2 「화면이 죽는 대가라면 내리지
않는 것이 맞다」). 다음 판단의 재료로 제안 1에 선택지를 적어 둔다.

**(다) 같은 틱 소멸 묶기 — 했다. 유휴에서는 묶을 것이 없었다.**
`drawFoes` 가 슬롯 배열을 한 번에 넘기고 `__foeDie` 가 다발로 받는다. 직접 측정
(한 틱에 6마리 동시 소멸):

| | `__foeDie` 호출 | 불티 | 소멸 연출 |
|---|---|---|---|
| 018 | 6회 | +36 | 6개 |
| 019 | **1회** | **+12** | 6개 |

연출 개수는 그대로고(마리마다 제자리에서 꺼진다) **불티 예산만 다발 전체로
나눈다**. 유휴 duty 가 안 내려간 이유도 여기서 보인다 — 방치 중에는 16회 소멸이
전부 **1마리짜리 다발**이라 묶을 것이 없다. 묶기가 버는 자리는 웨이브 끝처럼
여러 마리가 한 틱에 빠지는 순간이다.

### ③ §1 던전 연출 — 새 그림 0장

## 제안 (구현하지 말고 여기에 적을 것)

1. **유휴 duty 의 주인은 소멸 창 하나다** (②-나). 내리려면 셋 중 하나를 고르는
   판단이 필요하다 — ⑴ `DIE_MS` 320 → 220 (창 400 → 300ms, duty ≈ 8%),

   ⑶ 그대로 두기. ⑵ 는 「개체 수 = 남은 체력」 읽기를 해치지 않으면서 창 수를
   줄이지만, 방치 화면이 밋밋해진다. 사용자 감각이 필요한 자리라 손대지 않았다.
2. **`hidden()` 은 표시 계층에만 걸었다.** CORE 의 250ms 틱은 숨은 탭에서도 계속
   돈다(브라우저가 1초로 늦추긴 한다). 오프라인 델타가 이미 타임스탬프 한 줄이니
   **숨으면 틱을 멈추고 돌아올 때 델타로 따라잡는** 쪽이 배터리에 더 크게 남을
   수 있다. 다만 CORE 변경이라 계획 세션 판단 사항이다.

   쓰지만 같은 함수 하나로 제련 탭에도 얹을 수 있다 — 다음 바이옴이 어떤 색인지

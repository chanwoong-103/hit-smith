# 힉스필드 시험 — 판정 (2026-09-14, 계획 세션)

> **2026-09-14 정정.** 아래 §2-④ 에서 장갑을 낙제시킨 근거 하나가 틀렸다.
> **단계 간 실루엣 겹침이 높은 것은 결함이 아니라 이 프로젝트의 원칙이다**
> (등급은 부피가 아니라 밀도로 오른다 — ART-DIRECTION). 장갑 t1↔t2 0.89 는
> 원칙을 지킨 값이고, 오히려 무기의 0.71 이 단계마다 형태가 흔들렸다는 뜻이다.
> 그리고 **판정을 12배 확대·무채색으로 한 것**도 틀렸다. 같은 그림을 1×·2× 에
> 등급색으로 얹으니 손가락이 너클로 제대로 읽힌다.
> **결론: 무기 3장·장갑 3장 모두 1차 생성분으로 확정.** 옆모습 재생성 3장
> (v3a·v3b·v3c)은 기각 — 너클 혹이 떨어져 보이거나(v3a), 방패로 읽히거나(v3b),
> 손가락 다섯이 벌어졌다(v3c, 015 가 금지한 실패 모드).
> 사용자 판정과 재측정이 같은 곳을 가리켰다.

대상: 2048×2048 시트 1장, 무기 t1·t2·t3 + 장갑 t1·t2·t3.
질문: **AI 원화를 우리 팔레트 인덱스 문자열로 바꿨을 때 쓸 만한가.**

   있었다. 주기 51.2px(2048/40) 격자를 모형으로 세워 예측색과 ±22 이내 · 무채색
   인 칸을 배경으로 제거했다. **다음부터는 단색 배경을 요구할 것.**
2. 연결 요소 6개 추출 → 부위별 공통 배율로 32×32 축소(면적 평균, 피복 42%
   이상을 불투명으로) → 휘도 1차원 k-means(k=4)로 외곽선/본체어둠/본체/
   하이라이트 배정.
3. 워터마크(HIGGSFIELD AI)가 우하단 장갑 t3 의 아랫단을 물었다. **다음부터는
   우하단을 비워 둘 것.**

## 2. 판정 넷

**① 축 서명 무충돌 — 통과.** 무기 47°, 장갑 91°. 44° 벌어졌고 단계별 흔들림은
무기 1.4°, 장갑 1.9° 안이다. 프롬프트에 축을 적는 방식이 먹힌다.

**② t1·t2·t3 경계상자 동일 — 통과.** 원본 경계상자가 무기 590/603/616 ×
654/655/654, 장갑 438/425/438 × 681/693/648(t3 은 워터마크에 물린 값).
높이 편차 0.2%. **"등급은 부피가 아니라 밀도"가 지켜졌다** — t3 에 뿔·날개·
가시가 붙지 않았다. 이건 프롬프트의 성과다.

**③ 등급 15종 파생 — 통과.** 인덱스 문자열에 팔레트만 갈아 끼워 15장이 나온다
(`higgsfield-01-grades15.png`). 다만 **원화의 색은 전부 버려진다** — t1 의 갈색
가죽도 t3 의 금 상감도 휘도 4단으로만 남는다. 색을 넣어 뽑는 건 낭비였고,
더 나쁘게는 t1 에서 갈색과 쇠의 휘도가 붙어 안쪽이 뭉갰다.
→ **다음부터 흑백으로 뽑는다.**

**④ 검정 실루엣 테스트 — 무기 통과, 장갑 낙제.**
- 무기: 대각선 칼날 + 십자가드 + 폼멜이 형태만으로 읽힌다. 세 장이 한 무리다.
- 장갑: 세 장 모두 **땅콩 모양 덩어리**다. 장갑으로 읽히지 않는다. 그리고
  t1↔t2 겹침이 0.89 — **실루엣이 단계 정보를 하나도 못 나른다**(무기는 0.71).
  손가락은 `preview` 에서 **위로 선 빗살 4개**로 보인다. 사용자 지적이 맞다.

## 3. 장갑이 왜 실패했나 — 규칙 두 개가 서로를 막았다

015 이후 우리가 든 규칙은 둘이다.
- (ART-DIRECTION) **손가락은 돌출이 아니라 홈이다** — 벌레 다리를 막으려고.
- (012/015) **부위는 검정 실루엣만으로 갈려야 한다.**

**정면 주먹 자세에서는 이 둘이 동시에 성립하지 않는다.** 손가락을 홈으로 밀어
넣으면 정보가 전부 안쪽 음영으로 가고 바깥 윤곽에는 아무것도 안 남는다. 남는
건 타원이다. 015 의 재드로잉이 "벌레 다리"는 고쳤지만 **고친 자리에서 실루엣이
비었다** — 그게 지금 이 땅콩이다.

**고칠 것은 손가락 처리가 아니라 자세다.** 옆모습으로 세우면 윤곽 자체에 단이
생긴다: 아래 넓은 커프 → 좁은 손목 → 손목보다 넓은 주먹 덩어리 → 위쪽 모서리에
너클 혹 셋 → 왼쪽 중간에 엄지 혹 하나. 홈 규칙을 깨지 않으면서 실루엣에 정보가
돌아온다. 세로축(91°)도 그대로 유지된다.

## 4. 파이프라인 쪽 수확 — 외곽선은 우리가 고친다

축소하면 원화의 안티에일리어싱이 중간 휘도로 뭉개져 **외곽선 적중이 33~79%**
까지 떨어진다. 014 의 `OC1`·`OC2` 를 그대로 못 넘긴다.

고치는 법은 프롬프트가 아니라 후처리다: **축소 후 마스크의 테두리 한 칸을
인덱스 1로 강제한다.** 적중률이 전부 100% 가 되고, 무기 세 장이 눈에 띄게
또렷해졌다(`higgsfield-01-fixed32.png` 대 `higgsfield-01-raw32.png`).
공짜이고 되돌릴 수 있다. **AI 에 "1px 외곽선"을 부탁하지 말고 우리가 긋는다.**

## 5. 결론

**전체 전환 — 조건부 진행.**
- 무기 축은 그대로 간다. 프롬프트 형식(공통 규칙 + 축 지정 + 금지 목록)이 먹혔다.
- 장갑은 **자세를 바꿔 재생성**한다. 2차 프롬프트는 `higgsfield-prompts.md` §2.
- 생성 규칙 넷을 고친다: **흑백 / 단색 배경 / 우하단 비움 / 외곽선은 우리가**.
- 아직 `forge.html` 에 넣지 않는다. 몹까지 2차로 뽑아 같은 네 판정을 통과한 뒤,
  구현 세션에 한 번에 넘긴다(손그림 총량 38장 상한은 그대로다 — 새로 그리는
  것이 아니라 **갈아 끼우는 것**이므로 총량은 변하지 않는다).

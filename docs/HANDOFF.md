## 6. 작업 방식 — 세션 셋과 사용자

```
사용자 ──요구──▶ 계획 세션(총괄) ──plans/NNN-*.md──▶ 코딩 세션 ──구현 결과──▶ 검증 세션
   ▲                  │  ROADMAP·DESIGN·BALANCE 갱신권          │                 │
   └──「붙여 넣을 메시지」──┴──────────────── 판정 ◀──────── 검증 기록 ◀──────────┘
```

- **계획 세션만** 순서를 정하고 지시서를 쓰고 ROADMAP 을 고친다. 코딩 세션은 지시서 밖을 안 고친다 —
  아이디어는 「제안」 절에 적어 넘긴다.
- **지시서 절 구성**: 상태 / 왜 / 변경할 것 / 바꾸지 말 것 / 완료 조건 / 구현 결과 / 제안 / 검증 기록.
  「상태:」 줄이 **락**이다 — 진행 중인 코딩 지시서가 있으면 다른 것은 시작하지 않는다(단일 파일이라 병합 불가).
- **변경의 무게를 둘로**: 가벼운 변경(표시만, 상태·저장·수치 안 건드림)은 코딩 세션이 스스로 닫는다.
  무거운 변경(로직·저장 형식·새 메커니즘·광고/플랫폼)만 독립 검증. 애매하면 무겁다.
  — 모든 지시서에 같은 무게를 걸었더니 **메시지를 나르는 사용자가 병목**이 됐다.
- **검증 통과 = 커밋.** 커밋 메시지에 지시서 번호와 md5. 이전 빌드는 `git show <커밋>:파일` 로 꺼낸다.
  **저장소는 첫날 만든다** — 이번엔 2026-09-27(030 무렵)에야 만들어 두 번이나 「이전 빌드」를 재현하지 못했다.
- **계획 세션이 사용자에게 줄 것**: 붙여 넣을 메시지(코드 블록 그대로), 실행할 명령, 검문 숫자
  (예: 「마지막 줄이 `9F805E49` 로 시작해야 한다, 다르면 멈출 것」).

## 7. 절대 원칙 틀 (무관리 수익 게임용)

Hit Smith 의 원칙 1~8 중 **장르와 무관한 것**. 새 게임 CLAUDE.md 첫 절에 그대로 옮긴다.

1. **무관리** — 서버 0, 리더보드 0, 저장은 localStorage(+포털 클라우드 저장). 오프라인 진행은 타임스탬프 델타 한 줄.
2. **의존성 0, 빌드 스텝 0, 파일 하나.** 라이브러리는 「쓸 API 가 몇 개인가」를 먼저 센다
   (Phaser 를 들였다가 API 넷 쓰려고 315KB, 가장 비싼 버그 셋이 전부 그 API 함정 → 걷어내니 gzip −86%).
   포털 SDK 는 그 포털 도메인에서만 동적으로 불러오고, 게임은 어댑터(`PLAT`)만 부른다.
3. **콘텐츠는 공식으로.** 손그림은 상한을 숫자로 정한다(우리는 18장, 나머지는 팔레트 스왑).
4. **CORE/VIEW 구획.** 로직은 바이트 단위로 보존하고 회귀 기준을 해시로 잡는다(`days.js` 출력 md5).
5. **포털 정책을 설계 단계에서** — 사행성 용어·비주얼 금지 목록을 영어까지 첫날 만든다.
6. **광고 보상은 진행도에 비례 금지**(후반 지수 폭발). 시간형·정액형만. 그리고 **병목인 자원을 준다** —
   병목이 아닌 자원은 아무도 원하지 않는다.

## 8. 검증 규율 — 가장 비쌌던 열 가지

CLAUDE.md 「검증 세션」 절의 원문이 근거다. 여기는 장르와 무관한 핵심만.

1. **통과 / 실패 / 측정 불가** 셋으로 끝낸다. 프로브가 대상을 못 찾으면 통과가 아니라 측정 불가(종료 코드 2).
2. **새 검사는 결함 있는 빌드(변이)에 물려 실제로 우는지 보고 나서** 통과를 보고한다.
3. **카운터는 「했다」를 말하지 「보인다」를 말하지 않는다.** 캔버스는 픽셀로, 「막았다」는 막힌 것을 재서.
   프레임 검사와 픽셀 검사는 짝으로(안 그리면 빠르다).
4. **화면을 재는 검사와 규칙을 재는 검사는 다르다.** 101개 검사가 그림을 보는 동안 몹이 먼 쪽부터 죽는 건 아무도 안 봤다.
   「시간이 흐르면 무슨 일이 일어나는가」(방치 실측)를 따로 둔다 — 033 은 방치 5.3초 만에 게임이 섰다.
5. **보상 버튼은 「몇 번까지, 무엇을 대가로」를 검사에 둔다** — 026 광고 버튼이 무한 충전이었다.
6. **기계가 사람 함수를 감싸면 드문 부작용이 주 효과가 된다** — 부작용 목록부터 적는다(033 `newWave` 246회).
7. **같은 빌드를 두 번 재서 노이즈 바닥부터.** 절대 문턱을 문서에 박지 않는다. 문턱에는 「무엇을 세는지」를 붙인다.
8. **판정 직전에 원본과 지시서의 수정 시각을 다시 본다**(4시간 33분 묵은 사본으로 반려문을 쓴 적이 있다).
   검사가 도는 동안엔 대상 파일을 얼린다.
9. **문서 주장도 산출물이다 — 파일로 확인한다.** 「README 에 절을 추가했다」가 실물에 없었다. 크기 말고 md5.
10. **여러 세션이 쓰는 파일은 쓰기 직전에 다시 읽고 자기 절만 덧붙인다**(수정 시각 가드). 이번 주에만 두 번
    다른 세션의 절이 통째로 지워졌다(034, 035).

계획 세션 몫 셋: **사용자가 가리킨 것은 `#id` 와 들어 있는 곳까지 적는다**(023 은 엉뚱한 요소를 옮겨 코드 0줄로 끝났다).
**근거는 숫자로만** — 계획 세션의 「페이싱 전부 무효」 주장도 실측에 틀렸다(026). **깃발은 원인이지 효과가 아니다.**
